# Secret AI

Telegram-бот на Python: текстовые диалоги через OpenAI Responses API, фото (vision), голосовые через `whisper-1`, отдельная SQLite-память для каждого Telegram ID. Работает в личных сообщениях. Модель по умолчанию — `gpt-5.6-luna`.

## Команды

- `/start` — приветствие и помощь.
- `/reset` — удалить свою историю.
- `/myid` — показать свой Telegram ID.
- `/app` — открыть Mini App в стиле iOS 26 (кнопка «Secret AI» у поля ввода тоже открывает его): приложения в одно касание, готовые сценарии, режим ответа и модель.
- `/emojiid` — показать ID анимированного (custom) эмодзи из сообщения.
- `/mode`, `/export`, `/help` — режим ответа, выгрузка истории, справка.

Отправьте текст, голосовое до 10 минут/19 МБ или фото с подписью-вопросом. Без подписи бот описывает фото. Перед ответом на голосовое показывает расшифровку. Ответы модели — на языке пользователя; служебные сообщения — на русском или английском. Ответы делятся на части до 4000 единиц UTF-16, включая эмодзи.

## Переменные окружения

| Имя | Значение |
| --- | --- |
| `TELEGRAM_TOKEN` | Обязательно: токен от @BotFather |
| `OPENAI_API_KEY` | Обязательно: ключ OpenAI API с доступом к модели и доступным балансом |
| `OPENAI_MODEL` | По умолчанию `gpt-5.6-luna`; для фото нужна vision-модель |
| `ALLOWED_USERS` | Telegram ID через запятую, например `123456789,987654321`. Пусто — доступ всем |
| `PORT` | HTTP-порт, по умолчанию `10000`; на Render задаётся платформой |
| `BRAND_EMOJI` | Эмодзи-логотип в «Думаю…», по умолчанию `✨`. Для анимированного логотипа — запасной символ, к которому привязан ваш эмодзи |
| `BRAND_EMOJI_ID` | ID анимированного эмодзи с вашим логотипом (см. ниже). Пусто — обычный эмодзи |
| `DRAFT_REPLIES` | `1` по умолчанию: нативный стриминг Telegram. `0` — старый режим с редактированием сообщения |
| `PUBLIC_URL` | Публичный HTTPS-адрес сервиса для Mini App. На Render берётся из `RENDER_EXTERNAL_URL` автоматически |
| `ENCRYPTION_KEY` | Ключ шифрования токенов сервисов в базе (любая длинная случайная строка). Если пусто — выводится из `TELEGRAM_TOKEN`; при смене токена бота подключения придётся сделать заново |
| `OPENAI_MODELS` | Необязательно: дополнительные модели для выбора в Mini App через запятую, например `gpt-5.6-sol,gpt-6-astra`. По умолчанию у всех `OPENAI_MODEL` |
| `PIPEDREAM_CLIENT_ID`, `PIPEDREAM_CLIENT_SECRET`, `PIPEDREAM_PROJECT_ID` | Каталог приложений в Mini App (см. ниже). Без них работает только GitHub и свой MCP |
| `PIPEDREAM_ENVIRONMENT` | `production` по умолчанию; `development` — для тестов |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | Необязательно: свой GitHub OAuth App. Без них бот сам создаёт GitHub App при первом подключении |
| `DATABASE_PATH` | По умолчанию `memory.db`; с диском Render используйте `/var/data/memory.db` |

Все секреты читаются только из окружения. `.env` автоматически не загружается. Не добавляйте реальные ключи в исходники, README, команды сборки или GitHub.

## Деплой на Render (Web Service)

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите Telegram-токен. Создайте ключ в [OpenAI Platform](https://platform.openai.com/api-keys).
2. В [Render](https://dashboard.render.com/) выберите **New → Web Service**, подключите GitHub и предоставьте доступ к приватному репозиторию `secret-ai`.
3. Выберите ветку `main`, язык **Python 3**, корневую директорию оставьте пустой.
4. **Build Command:** `pip install -r requirements.txt`
5. **Start Command:** `python bot.py`
6. В **Environment** добавьте `PYTHON_VERSION=3.11.11`, `TELEGRAM_TOKEN`, `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-5.6-luna` и при необходимости `ALLOWED_USERS`.
7. Для постоянной работы выберите платный экземпляр. Добавьте **Persistent Disk** с точкой монтирования `/var/data`, затем `DATABASE_PATH=/var/data/memory.db`.
8. Укажите **Health Check Path:** `/health`. HTTP-сервер слушает `0.0.0.0:$PORT`. Проверка подтверждает работу процесса, но не доступность OpenAI или Telegram.
9. Нажмите **Create Web Service**, дождитесь запуска и напишите боту `/start`.

Используется long polling: публичный webhook и отдельный домен для Telegram не нужны. Держите **один экземпляр** с одним Telegram-токеном. Не запускайте одновременно локальную копию и Render: Telegram выдаст конфликт polling. Подключённый persistent disk также исключает обычное перекрытие экземпляров при деплое.

**Ограничения бесплатного Render:** сервис засыпает после 15 минут без входящего трафика. Исходящий polling Telegram не обеспечивает постоянную работу; спящий бот не проснётся от сообщения Telegram. Без persistent disk память теряется при перезапуске/деплое. Для непрерывной работы с сохраняемой SQLite используйте платный сервис и диск.

## Локальный запуск

Нужен Python 3.10+ (рекомендуется 3.11). Создайте виртуальное окружение, установите зависимости и задайте переменные окружения средствами своей системы:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Задайте TELEGRAM_TOKEN и OPENAI_API_KEY в окружении.
python bot.py
```

`imageio-ffmpeg` поставляет FFmpeg для преобразования Telegram OGG/Opus в WAV на поддерживаемых платформах, включая Linux x86_64 Render. На другой архитектуре может потребоваться системный FFmpeg и переменная `IMAGEIO_FFMPEG_EXE` с его путём.

## Анимация «Думаю» и печать ответа (как у Mira)

Логотип Secret AI — белая звезда-искра с глазами. В Mini App она «дышит», поворачивается, оглядывается и моргает. В чате тот же логотип стоит перед «Думаю…»: при запуске бот сам создаёт набор эмодзи из `webapp/logo-emoji.webm` (владелец — владелец бота) и использует его. Telegram показывает такие эмодзи от ботов, только если у владельца бота есть Telegram Premium; иначе бот покажет обычный `✨`.

Пока модель думает, бот показывает черновик сообщения: `логотип Думаю` и таймер `0с, 1с…`, фразы меняются каждые 4 секунды. Потом ответ сам «печатается» плавной анимацией. Это нативные черновики Telegram (`sendMessageDraft`, Bot API 9.5+): они не мигают и не упираются в лимит правок. Готовый ответ отправляется обычным сообщением с кнопками. Если Telegram не поддерживает черновики, бот автоматически переходит на анимацию через редактирование сообщения.

### Свой анимированный логотип

1. Подготовьте логотип в PNG, лучше квадратный и с прозрачным фоном.
2. Сделайте из него видео-эмодзи (100×100, до 3 с, до 64 КБ):
   ```bash
   python tools/make_emoji.py logo.png emoji.webm --style pulse   # или spin / bounce
   ```
3. В [@Stickers](https://t.me/Stickers): `/newemojipack` → **Video emoji** → отправьте `emoji.webm`, укажите эмодзи-замену (например `✨`), затем `/publish`.
4. Напишите своему боту `/emojiid` и вставьте этот эмодзи из набора. Бот ответит строкой с `BRAND_EMOJI` и `BRAND_EMOJI_ID`.
5. Добавьте эти переменные в Environment на Render и перезапустите сервис.

Боты могут показывать кастомные эмодзи, только если у владельца бота есть Telegram Premium (или у бота купленный юзернейм на Fragment). Иначе Telegram отклонит эмодзи, и бот покажет обычный `BRAND_EMOJI` — ответы при этом не ломаются.

## Mini App

`/app` или кнопка меню открывают Mini App в стиле iOS 26 Liquid Glass: стеклянные карточки и плавающий таб-бар, анимированный логотип (звезда-искра с глазами дышит, оглядывается и моргает), пружинные анимации, тактильная отдача. Поддерживаются тёмная и светлая темы Telegram. Вход проверяется подписью Telegram (`initData`); `ALLOWED_USERS` действует и здесь.

- **Агент** — приветствие, выбор модели, быстрые сценарии и ваши подключения.
- **Открытия** — готовые сценарии. Нажали — запрос уходит в чат, и бот сразу отвечает. Если сценарию нужно приложение (Gmail, Notion…), Mini App сначала предложит его подключить.
- **Приложения** — каталог с поиском. Нажмите «Подключить», войдите в аккаунт сервиса, и всё. Ни URL, ни ключей вводить не нужно.
- **Настройки** — режим ответа, модель, GitHub, свой MCP-сервер, память.

### Каталог приложений в одно касание (Pipedream Connect)

Каталог и вход в сервисы обеспечивает [Pipedream Connect](https://pipedream.com/docs/connect): больше 2 500 приложений с готовым OAuth. Токены аккаунтов пользователей хранит Pipedream; бот знает только ключи своего проекта.

1. Зарегистрируйтесь на [pipedream.com](https://pipedream.com), создайте **Project** и скопируйте его ID (`proj_…`) — это `PIPEDREAM_PROJECT_ID`.
2. В **Settings → API** создайте OAuth-клиент: получите `PIPEDREAM_CLIENT_ID` и `PIPEDREAM_CLIENT_SECRET`.
3. Добавьте три переменные в Environment на Render и перезапустите сервис. Для боевых пользователей окружение `production`. Его условия (бесплатный лимит, тарифы) смотрите в Pipedream.

После подключения приложение становится для модели удалённым MCP-сервером Pipedream: бот сам вызывает его инструменты, например «найди в Gmail письмо от …», «создай страницу в Notion», «что у меня в календаре завтра». Действия выполняются **без отдельного подтверждения**. Отключить приложение можно в его карточке.

### GitHub — одна кнопка

В Mini App нажмите «Подключить GitHub», разрешите доступ на GitHub и выберите репозитории. Токены и настройки на Render не нужны.

В самый первый раз GitHub покажет владельцу бота страницу «Create GitHub App»: так бот один раз создаёт себе приложение на GitHub ([App Manifest](https://docs.github.com/apps/sharing-github-apps/registering-a-github-app-from-a-manifest)). Ключи этого приложения бот сохраняет в своей базе в зашифрованном виде. После этого всем пользователям хватает одной кнопки. Токены пользователей обновляются автоматически.

Владельцем бот считает самого раннего пользователя в истории чата, а если её нет — первого, кто им воспользовался. Поэтому после нового деплоя сначала откройте бота сами. Вместо автоматического приложения можно задать `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET` своего OAuth App (callback: `https://<ваш-сервис>/oauth/github/callback`). Вход по fine-grained токену остался в карточке GitHub («Войти по токену»).

После этого просто пишите: «покажи мои репозитории», «в репо secret-ai поменяй заголовок README на …», «удали old.py», «сделай это в ветке feature и открой pull request». Бот сам смотрит и читает файлы, затем присылает **diff** (или файл `changes.diff`) с кнопками **✅ Применить / ❌ Отмена**. Без подтверждения ничего не меняется. Все правки уходят одним коммитом. Если файл успели изменить после предложения, бот откажется применять и попросит повторить. Неподтверждённые изменения живут 1 час.

### Свой MCP-сервер

Настройки → «Свой MCP-сервер»: название, HTTPS-URL и ключ, если нужен. Модель вызывает инструменты сервера сама, **без отдельного подтверждения**, поэтому подключайте только доверенные сервисы. Токены хранятся в SQLite в зашифрованном виде.

## Память и обработка ошибок

SQLite хранит последние 30 сообщений (примерно 15 пар вопрос–ответ) на пользователя. Запись пары и обрезка истории выполняются одной транзакцией. `/reset` удаляет историю только отправителя. Сообщения обрабатываются последовательно: это сохраняет порядок диалога и сброса памяти, но долгий запрос задерживает остальных пользователей.

В памяти сохраняются текст, расшифровки и ответы. Исходные голосовые временные файлы удаляются после обработки. Фото передаётся в текущий запрос OpenAI; в SQLite остаются подпись и отметка о фото, а также ответ модели. Для повторного анализа визуальных деталей отправьте фото снова. Тексты и медиа передаются OpenAI для обработки; `store=False` отключает хранение Responses для последующего получения, но не заменяет правила хранения данных провайдера.

Ошибки отдельных сообщений перехватываются; пользователю приходит понятное уведомление. В логи выводится только тип ошибки, без ключей и содержимого диалога. Некорректная конфигурация не запускает бота. Если закончился баланс API или модель недоступна, проверьте настройки OpenAI; бот не подменяет выбранную модель другой.

# Secret AI

Telegram-бот на Python: текстовые диалоги через OpenAI Responses API, фото (vision), голосовые через `whisper-1`, отдельная SQLite-память для каждого Telegram ID. Работает в личных сообщениях. Модель по умолчанию — `gpt-5.6-luna`.

## Команды

- `/start` — приветствие и помощь.
- `/reset` — удалить свою историю.
- `/myid` — показать свой Telegram ID.

Отправьте текст, голосовое до 10 минут/19 МБ или фото с подписью-вопросом. Без подписи бот описывает фото. Перед ответом на голосовое показывает расшифровку. Ответы модели — на языке пользователя; служебные сообщения — на русском или английском. Ответы делятся на части до 4000 единиц UTF-16, включая эмодзи.

## Переменные окружения

| Имя | Значение |
| --- | --- |
| `TELEGRAM_TOKEN` | Обязательно: токен от @BotFather |
| `OPENAI_API_KEY` | Обязательно: ключ OpenAI API с доступом к модели и доступным балансом |
| `OPENAI_MODEL` | По умолчанию `gpt-5.6-luna`; для фото нужна vision-модель |
| `ALLOWED_USERS` | Telegram ID через запятую, например `123456789,987654321`. Пусто — доступ всем |
| `PORT` | HTTP-порт, по умолчанию `10000`; на Render задаётся платформой |
| `DATABASE_PATH` | По умолчанию `memory.db`; с диском Render используйте `/var/data/memory.db` |

Все секреты читаются только из окружения. `.env` автоматически не загружается. Не добавляйте реальные ключи в исходники, README, команды сборки или GitHub.

## Деплой на Render (Web Service)

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите Telegram-токен. Создайте ключ в [OpenAI Platform](https://platform.openai.com/api-keys).
2. В [Render](https://dashboard.render.com/) выберите **New → Web Service**, подключите GitHub и предоставьте доступ к приватному репозиторию `secret-ai`.
3. Выберите ветку `main`, язык **Python 3**, корневую директорию оставьте пустой.
4. **Build Command:** `pip install -r requirements.txt`
5. **Start Command:** `python bot.py`
6. В **Environment** добавьте `PYTHON_VERSION=3.11.11`, `TELEGRAM_TOKEN`, `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-5.6-luna` и при необходимости `ALLOWED_USERS`.
7. Для постоянной работы выберите платный экземпляр. Добавьте **Persistent Disk** с точкой монтирования `/var/data`, затем `DATABASE_PATH=/var/data/memory.db`.
8. Укажите **Health Check Path:** `/health`. HTTP-сервер слушает `0.0.0.0:$PORT`. Проверка подтверждает работу процесса, но не доступность OpenAI или Telegram.
9. Нажмите **Create Web Service**, дождитесь запуска и напишите боту `/start`.

Используется long polling: публичный webhook и отдельный домен для Telegram не нужны. Держите **один экземпляр** с одним Telegram-токеном. Не запускайте одновременно локальную копию и Render: Telegram выдаст конфликт polling. Подключённый persistent disk также исключает обычное перекрытие экземпляров при деплое.

**Ограничения бесплатного Render:** сервис засыпает после 15 минут без входящего трафика. Исходящий polling Telegram не обеспечивает постоянную работу; спящий бот не проснётся от сообщения Telegram. Без persistent disk память теряется при перезапуске/деплое. Для непрерывной работы с сохраняемой SQLite используйте платный сервис и диск.

## Локальный запуск

Нужен Python 3.10+ (рекомендуется 3.11). Создайте виртуальное окружение, установите зависимости и задайте переменные окружения средствами своей системы:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Задайте TELEGRAM_TOKEN и OPENAI_API_KEY в окружении.
python bot.py
```

`imageio-ffmpeg` поставляет FFmpeg для преобразования Telegram OGG/Opus в WAV на поддерживаемых платформах, включая Linux x86_64 Render. На другой архитектуре может потребоваться системный FFmpeg и переменная `IMAGEIO_FFMPEG_EXE` с его путём.

## Память и обработка ошибок

SQLite хранит последние 30 сообщений (примерно 15 пар вопрос–ответ) на пользователя. Запись пары и обрезка истории выполняются одной транзакцией. `/reset` удаляет историю только отправителя. Сообщения обрабатываются последовательно: это сохраняет порядок диалога и сброса памяти, но долгий запрос задерживает остальных пользователей.

В памяти сохраняются текст, расшифровки и ответы. Исходные голосовые временные файлы удаляются после обработки. Фото передаётся в текущий запрос OpenAI; в SQLite остаются подпись и отметка о фото, а также ответ модели. Для повторного анализа визуальных деталей отправьте фото снова. Тексты и медиа передаются OpenAI для обработки; `store=False` отключает хранение Responses для последующего получения, но не заменяет правила хранения данных провайдера.

Ошибки отдельных сообщений перехватываются; пользователю приходит понятное уведомление. В логи выводится только тип ошибки, без ключей и содержимого диалога. Некорректная конфигурация не запускает бота. Если закончился баланс API или модель недоступна, проверьте настройки OpenAI; бот не подменяет выбранную модель другой.

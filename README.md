# Secret AI

## Восстановление сообщений бота в супергруппе

Необязательный пользовательский аккаунт-наблюдатель читает журнал удалений, а бот
восстанавливает сохранённые копии собственных сообщений. Удаления владельцем и самим
ботом исключены. Владелец и администраторы управляют восстановлением кнопками в
карточке группы Mini App. Команды также доступны: `/guard on`, `/guard status`,
`/guard off`. По умолчанию функция выключена; сначала
нужен локальный вход аккаунта и загрузка зашифрованной сессии на хостинг.
Пошаговая настройка hCloud, ограничения форматов и поведение при сбоях:
[deploy/GUARD_SETUP.md](deploy/GUARD_SETUP.md).

## Навыки, плагины и подключения

В Mini App откройте **Приложения → Навыки и плагины**. Можно установить готовые навыки
«Редактор», «Исследователь» и «Ревью кода», создать свой навык через форму или импортировать
самостоятельный `SKILL.md`, декларативный `plugin.json` либо ZIP. Перед установкой показаны
инструкции и предлагаемые подключения. Повторная установка с тем же ID требует явной замены.
Установленный пакет можно включить, отключить, отредактировать, скачать и удалить.

Навыки доступны в личном диалоге Telegram, голосовом режиме Live и задачах Mini App, включая
GitHub-проекты. Модель видит краткое описание включённых навыков и может прочитать полные
инструкции инструментом `load_skill` перед подходящей задачей. Навык можно назвать в запросе:
«Используй Ревью кода для этих изменений». Применение зависит от поддержки вызова инструментов
выбранной моделью. В общие группы, бизнес-секретаря и изолированные ответы на конкретное
сообщение личные навыки не передаются. Навыки не предоставляют новые права или инструменты.

Каждый пользователь видит только свои установки. Содержимое хранится в зашифрованном поле
существующей базы подключений и входит в её резервные снимки. Удаление пакета не отключает
приложения, подключённые пользователем отдельно.

Самостоятельный `SKILL.md` — UTF-8 Markdown с YAML-заголовком:

```markdown
---
name: meeting-notes
description: Превращает заметки встречи в решения и задачи
---
Выдели решения, открытые вопросы и задачи. Для каждой задачи укажи ответственного
и срок только при наличии их в исходном тексте. Не придумывай договорённости.
```

Формат `plugin.json` для пакета с несколькими навыками и рекомендациями подключений:

```json
{
  "id": "team-notes",
  "name": "Заметки команды",
  "description": "Итоги встреч и подготовка следующего шага",
  "version": "1.0",
  "skills": [{
    "id": "summary",
    "name": "Итоги встречи",
    "description": "Разбор заметок и переписки после встречи",
    "instructions": "Выпиши решения, задачи и открытые вопросы. Не придумывай сроки."
  }],
  "connectors": [{"label": "TeamDocs", "url": "https://example.com/mcp"}]
}
```

`example.com` здесь — пример: замените адрес реальным сервером. Подключение из пакета
добавляется отдельно кнопкой «Подключить»: проверьте адрес и введите ключ при необходимости.
Сам импорт ничего не авторизует и не обращается к серверу. Токены не входят в формат пакета.
В ZIP допускается один такой `plugin.json` со встроенными навыками либо набор
`skills/<имя>/SKILL.md` с необязательным декларативным `plugin.json`, описывающим пакет.
Лимиты: 24 пакета на пользователя, до 8 навыков и 8 рекомендаций подключений в пакете,
16 000 символов на инструкцию, 512 КиБ на загрузку и распакованное содержимое ZIP,
до 100 элементов архива. Скрипты, hooks, команды запуска, дополнительные файлы ресурсов
и локальные stdio-серверы не поддерживаются; это ограниченный формат, а не полная совместимость
с любыми пакетами Codex/Claude. Файлы архива не извлекаются на диск и код из них не запускается.

**Приложения → Мои подключения** показывает собственные MCP-серверы: их можно включать,
отключать и удалять. «Проверить инструменты» выполняет только MCP initialize/tools/list
с ограничением времени; операции приложений не запускаются. Ключи не возвращаются в интерфейс.
Поддерживаются публичные HTTPS endpoint'ы MCP Streamable HTTP с необязательным Bearer-ключом;
ключ передаётся отдельным полем, без query-параметров URL. Для OAuth используйте каталог.
Подключённые MCP-инструменты по-прежнему выполняются без отдельного подтверждения действия.

Прямые приложения ищутся по названию, идентификатору и описанию. При сбое внешнего каталога
они остаются доступны, а интерфейс показывает сообщение о сбое. Большие MCP-серверы делят
лимит 60 инструментов по очереди с другими приложениями. Собственные названия подключений
распознаются после перезапуска; сбой обновления одного OAuth-токена не скрывает остальные
прямые приложения. При большом числе подключений Pipedream явно названное приложение
получает приоритет в лимите 12 подключений на запрос. Каталог Pipedream по-прежнему требует настройки владельцем, а OAuth и
доступность сторонних сервисов зависят от их условий и разрешений пользователя.

Проверки расширений: `python -m unittest discover -s tests -p test_extensions.py` и
`node tests/extensions_smoke.cjs` (нужны Playwright, Chromium и зависимости Python).
Браузерная проверка использует настоящие HTTP-маршруты, временную SQLite и шифрование,
без Telegram-доставки и живых сервисов. `SECRET_TEST_PYTHON` задаёт путь Python для фикстуры.

## Подключение Oxion AI

Подключение Oxion AI активируется автоматически при наличии `OXIONAI_API_KEY` в переменных окружения хостинга (по умолчанию запрашивается и подтверждается флагманская модель Claude Sonnet 5). Чтобы отключить Oxion и вернуться к прежним провайдерам, задайте `OXIONAI_ENABLED=0` в переменных окружения хостинга. Ключ хранится только в переменных хостинга, не добавляется в GitHub и не вводится в чатах. Необязательные настройки:

- OXIONAI_BASE=https://www.oxionai.com/v1
- OXIONAI_MODELS=claude-sonnet-5 — точные ID из каталога Oxion, через запятую; первый становится исходной моделью по умолчанию. Пока список не задан, запрашивается только Claude Sonnet 5.

При OXIONAI_ENABLED=1 и наличии ключа Oxion полностью заменяет AnyModel и Reformboss для чата, групп и задач Codex. Каталог /v1/models должен подтвердить ID: неподтверждённые модели не предлагаются, а 401/403 или отсутствие модели не переключают запросы на старого провайдера. При временной сетевой ошибке используется только ранее подтверждённый каталог Oxion. Сохранённые выборы старых моделей исключаются из меню и цепочки резервирования.

Настройка касается моделей диалога; ключи генерации медиа не удаляются. Чтобы завершить тест, задайте OXIONAI_ENABLED=0 (или удалите этот флаг) и перезапустите бота — прежние подключения чата снова будут доступны. Пока тест явно не включён или ключ Oxion не добавлен, прежние модели продолжают работать.

/apistatus показывает активного провайдера и доступность запрошенных ID без раскрытия ключа. /speed проверяет реальный ответ (расходует токены провайдера). Для Oxion нужны права inference и models:read. Баланс аккаунта и доступность реального ключа не проверяются тестами репозитория.

Документация провайдера: https://www.oxionai.com/docs и https://www.oxionai.com/models. Пока подключение подготовлено для теста без ключа и публичного запуска, номер пользовательского релиза и текст текущей рассылки не меняются.

## Обновление: документы, напоминания и надёжность

На главной Mini App доступны «Документы», «Поиск в истории» и «Напоминания». Владелец также видит «Состояние».

- **Документы:** загрузка до 19 МБ (сохраняемые исходники: до 64 МиБ на пользователя и 128 МиБ на бота), создание/выбор проекта, список версий, выбор и удаление файла с подтверждением, выгрузка текста и отчёт Word/Markdown. Используется та же личная область проектов, что в Telegram; групповые файлы здесь не показываются.
- **Исправленные копии:** DOCX — точная уникальная замена в основном тексте, включая фрагменты на границе текстовых элементов; стиль вставки берётся с начала заменяемого фрагмента. XLSX — изменение существующей ячейки со значением по имени листа и адресу. Формулы не перезаписываются и не пересчитываются. Исходный файл не меняется; копия скачивается со списком правок. Для этой функции исходник нужно загрузить через Mini App. Это точечные правки пользователя, не автоматическое исправление моделью всего документа.
- **История:** поиск по сохранённым сообщениям личного диалога, с фрагментами и датами. Другие пользователи и групповые истории недоступны. Поиск не восстанавливает удалённые сообщения.
- **Повторяющиеся напоминания:** в Mini App или `/remind ID каждый понедельник в 10:00`, `/remind ID по будням в 18:00`, `/remind ID каждый день в 09:00`. Используется часовой пояс `/life tz Europe/Moscow`. Под уведомлением есть «Готово», отложить на 15 минут/час и перенести на 24 часа. Завершение задачи отменяет будущие напоминания.
- **Codex:** при перезапуске задача приостанавливается с сохранением проектных файлов; продолжение запускается кнопкой без дополнительного списания за перезапуск. GitHub-предложение после прерывания проверяется и собирается заново. До применения видны diff, сводка файлов и фактически выполненные команды проверки; при отсутствии запусков это написано явно. Применение выполняется асинхронно, сериализовано для задачи; сохранённый коммит используется повторно, если создание PR временно не удалось.
- **Состояние для владельца:** версия, свободное место, модели, активные задачи, время/ошибка резервирования и наблюдения по реальным запросам к провайдерам после запуска. Задержка до открытия потокового ответа не равна времени его полной генерации. Ключи и ответы провайдеров не отображаются.
- **Резервирование:** при настроенном `DATABASE_URL` хранятся до 24 версий с проверкой целостности SQLite. Восстановление всей базы требует подтверждения владельца и применяется при следующем запуске; намерение сохраняется в Postgres и переживает замену диска. Перед откатом сохраняется текущее состояние. При неудаче восстановления на чистом диске бот останавливается, сохраняя старую резервную копию. Максимальный размер распакованного снимка — 256 МиБ.

Исправлены выбор ветки ZIP-загрузки, проверка Git checkout/reset, путь локальных зависимостей, продолжение работы после ошибки их установки, обработка таймаутов HTTP-моста, одновременное применение задачи, удаление бинарных файлов GitHub и изменение времени ежедневного уведомления в тот же день.

Проверки: Python unittest, интеграционные сценарии с отдельным Postgres, игровая логика Node.js и браузерные сценарии Chromium/WebKit выполняются workflow Verify. Они не используют реальные ключи моделей и Telegram.


Telegram-бот на Python: текстовые диалоги, фото (vision), голосовые, отдельная SQLite-память для каждого Telegram ID и групп. Текущая модель чата — Grok 4.7; маршруты и проверка доступности описаны ниже.

## Поиск музыки

В личке или группе напиши `найди песню название и исполнитель`, например
`найди песню Кино Спокойная ночь`. В группе можно написать
`@имя_бота найди песню Кино Спокойная ночь`. Бот показывает до пяти
вариантов с названием и длительностью; нажатие кнопки отправляет полный
MP3 через Telegram Audio. Выбрать вариант может автор поиска.

Отдельной команды нет. Создание песен и `/song` удалены. Поиск работает
без языковой модели, FAL_KEY и платных музыкальных API. Списки действуют
15 минут; после перезапуска нужно повторить поиск. Загружаются доступные
треки из YouTube длительностью до 20 минут и размером до 45 МиБ.
Ограниченные источником записи могут не скачаться — бот предложит другой
вариант. Аудио преобразуется целиком, без обрезки; временные файлы удаляются
после отправки. Повторная отправка использует Telegram file_id.

Зависимости `yt-dlp[default]` и `deno` устанавливаются через requirements.txt;
FFmpeg уже поставляется с imageio-ffmpeg. Если бот не видит обычные сообщения
в группе, используй @упоминание бота или отключи Privacy Mode в BotFather.

## Текущее состояние моделей

В Telegram и Mini App разрешена только Grok 4.7: AnyModel — основной провайдер, Reformboss (`https://api.reformboss.com/v1`) — резервный. Она становится моделью по умолчанию; старые выборы Claude и DeepSeek не используются. DeepSeek отключена. Переписка сохраняется.

Добавь `REFORMBOSS_API_KEY` в `.env` на сервере; адрес можно переопределить через `REFORMBOSS_BASE`. Сам ключ не добавляй в репозиторий. При запуске проверяется каталог нового шлюза: для AnyModel разрешён подтверждённый каталогом ID `xai/grok-4.7` (без суффикса `fast`). Также сохранена поддержка ID Grok 4.7 Fast для шлюзов, которые явно возвращают их в каталоге. Версии 4.6, маршруты `gcli` и генерация изображений не включаются. Для основного маршрута задай `ANYMODEL_API_KEY` и при необходимости `ANYMODEL_BASE`; используется существующий клиент AnyModel. Если ключ AnyModel не задан или точной модели нет в его каталоге, используется подтверждённый маршрут Reformboss. Кэш подтверждённых ID хранится отдельно для каждого провайдера. Если ни один настроенный шлюз не подтвердил эту модель и нет подходящего подтверждённого кэша, список остаётся пустым: другие версии и старые провайдеры не подключаются. Подтверждённые шлюзом ID сохраняются: если каталог временно не отвечает после перезапуска, бот использует ранее подтверждённый ID только разрешённой Grok. При отсутствии подтверждённого ID запросы не отправляются наугад. Подключение перепроверяется каждую минуту, а при пустом списке — также по сообщению с ограничением частоты. Отказ одного запроса не удаляет единственную модель навсегда; ошибки доступа/квоты продолжают показываться как ошибки сервиса. Работа реального ключа из этой среды не проверяется.

Для меньшей задержки включён `CHAT_REASONING_EFFORT=low`, если шлюз поддерживает этот параметр. Ответы передаются потоком; обычный чат не ждёт обновления GitHub-токена. Владелец может проверить конфигурацию и точные имена моделей командой `/apistatus` (ключи не выводятся), а реальный ответ — командой `/speed`. Генерация фото/видео и озвучка настраиваются отдельно.

## Работа с документами

Отправь файл в личку боту с подписью «Найди ошибки», «Объясни содержание», «Проверь расчёты» или своим вопросом. Без подписи бот делает краткий обзор, ищет ошибки и предлагает исправления с указанием места. В группе добавь @упоминание бота в подпись или ответь файлом на его сообщение.

Поддерживаются PDF с текстовым слоем, DOCX, XLSX, PPTX, TXT/MD/CSV/JSON/XML, текстовые конфиги и исходники, ZIP, APK и IPA. Размер файла — до 19 МБ. Для старых DOC/XLS/PPT нужна копия в новом формате. Сканы PDF и встроенные картинки не распознаются: отправь нужную страницу фотографией. Формулы Excel показываются вместе с сохранёнными значениями, но не пересчитываются; даты/форматирование представлены как хранимые значения.

Можно уточнять по выбранному файлу («Проверь вторую строку», «Объясни третий пункт») или ответить на исходный файл. Извлечённый текст сохраняется отдельно для каждой пары пользователь/чат и переживает перезапуск. `/files` позволяет выбрать ранее загруженный файл. `/reset` удаляет все проекты и сохранённые документы этого пользователя во всех чатах; полный сброс памяти также удаляет их.

APK/IPA и ZIP не запускаются и не распаковываются на диск. Бот видит структуру и ограниченную выборку текстовых файлов, читает в том числе бинарный `Info.plist` из IPA и указывает отсутствующие обязательные элементы. Бинарный AndroidManifest AXML, DEX/машинный код и подписи не декодируются; статический отчёт не подтверждает безопасность или работоспособность приложения. Доступные сведения и ограничения передаются модели явно.

Лимиты разбора: 60 000 символов текста, первые 100 страниц PDF, до 2 000 записей и 80 МБ суммарного размера внутри ZIP; читаемый элемент архива — до 4 МБ. Для архивов показываются первые 100 имён и не более 20 небольших текстовых файлов. О пропущенном содержимом бот предупреждается. Разбор выполняется в отдельном процессе с таймаутом 30 секунд и ограничениями CPU/памяти на Linux; одновременно разбираются максимум два файла.

Новые зависимости ставятся через `requirements.txt`; автообновление бота устанавливает их перед перезапуском. Дополнительный ключ API для чтения файлов не нужен — извлечённый текст обрабатывает текущая Grok. Загрузка документов через Mini App теперь доступна в разделе «Документы» на главной.

## Шесть новых возможностей: рабочие проекты

1. **Проекты с несколькими файлами.** `/project create Мой бот` создаёт и открывает проект. Следующие загрузки попадают в него. `/project` показывает список и кнопки, `/project open ID` открывает существующий, `/project off` возвращает входящие и обычный чат. Вопросы в открытом проекте учитывают выбранные фрагменты актуальных версий его файлов; в контексте есть список источников и ограничения.
2. **Файлы и версии.** `/files` показывает ID, имена, версии и выбранный файл. При изменении текста повторная загрузка того же имени создаёт следующую версию; идентичная загрузка не дублируется. `/files use ID` фокусирует вопросы/отчёты на конкретной версии; повторное открытие проекта возвращает работу со всеми актуальными файлами. `/files export ID` отдаёт извлечённый текст. `/files delete ID` и `/project delete ID` удаляют данные только после подтверждения кнопкой. Ранее полученные ответы остаются в истории до `/reset`.
3. **Поиск по содержимому.** `/find запрос` находит и показывает подходящие фрагменты в последних версиях файлов текущего проекта (или входящих), с ID источника, версией и положением. Поиск лексический, по извлечённому тексту, без OCR и поиска по бинарному коду.
4. **Сравнение версий.** `/compare` сравнивает две последние загрузки в текущем проекте; `/compare ID1 ID2` задаёт направление явно. Бот показывает число добавленных/удалённых строк, присылает unified diff и объясняет существенные изменения через текущую модель. Нумерация строк, добавленная при чтении TXT/DOCX, не создаёт ложные изменения. Сравнивается извлечённый текст, не оформление; лимит — первые 6 000 строк и 80 000 символов diff, ограничения помечаются явно.
5. **Отчёты для скачивания.** `/report` или `/report Проверь расчёты и выпиши риски` создаёт отчёт по текущему проекту/выбранному файлу в Word (`.docx`) и Markdown (`.md`), с выводами, местами в источниках и ограничениями. Это новый отчёт, не редактирование исходного Word/Excel.
6. **Диагностика логов и исходников.** `/diagnose` разбирает выбранный файл, `/diagnose ID` — конкретный. Типовые шаблоны ошибок Python, авторизации, квоты, таймаутов, SQLite, прав доступа и места на диске даются модели как гипотезы, затем она предлагает порядок проверки и исправления. Ответ приходит в чат и `.txt`. Приложение/код не запускаются; секреты распространённых форматов скрываются в диагностике и отчётах.

`/project help` — памятка в Telegram. Команды есть в меню бота. Они работают в личке и группах: доступны только файлы отправителя из текущего чата, кнопки привязаны к пользователю. В группах учитываются ограничения допуска и режим тестирования.

Ограничения хранения: до 8 проектов на пользователя в чате, 30 файлов/версий на чат и 150 на пользователя суммарно. При заполнении бот предлагает удалить ненужное, не удаляет старые файлы автоматически. Контекст проекта ограничен 50 000 символов выбранных фрагментов плюс список источников/предупреждения. Старый одиночный документ мигрирует во входящие один раз; файлы/проекты переживают перезапуск.

Модель остаётся единственной — Grok 4.7 через текущий ключ. Сравнение, отчёты и диагностика используют тот же API; проекты, хранение, лексический поиск и выгрузка извлечённого текста работают локально. Новые зависимости для этих шести функций не нужны.

## Команды

### Сериал про группу

- `/serial` — создать следующую серию по сохранённой переписке за последние 7 дней.
- `/serial on` — включить автоматический выпуск раз в 7 дней; `/serial off` — выключить.
- `/serial status` — число серий, доступная история и время следующего выпуска (UTC).
- `/serial help` — помощь. Создание и расписание доступны администраторам группы.

Формат — вертикальный MP4 540×960, анимированный комикс: 6–8 кадров, разные синтетические голоса персонажей, встроенные русские субтитры и тихая оригинальная музыка. Иллюстрации создаёт существующий бесплатный сервис изображений; если он недоступен, используются локальные рисунки. Это монтаж иллюстраций с движением камеры, а не полноценная генерация видео актёров. Сначала проверяется бесплатная озвучка Microsoft Edge. Если прямое соединение не работает, используются настроенные AnyModel TTS (Edge, затем Fish) или включённый OpenAI TTS; доступность и списание за эти маршруты зависят от подключённого провайдера. Тембр и скорость персонажей для резервных маршрутов меняются локально. Неудачные голосовые маршруты временно пропускаются. Сценарий использует уже подключённую модель чата.

Невалидный сценарий автоматически запрашивается повторно один раз. При неудаче бот показывает этап (`script`, `voice`, `render`, `upload`, `timeout`) и класс ошибки; этот код также сохраняется для `/serial status`. Ответы провайдеров не публикуются в группе; трассировка доступна в журнале сервера. Сюжет продвигается только после подтверждённой отправки.

Нужно хотя бы 12 сохранённых сообщений за неделю. Бот должен получать переписку: назначьте его администратором или отключите Group Privacy в @BotFather (после изменения при необходимости добавьте бота в группу заново). История до добавления бота недоступна. Реплики — художественная выдумка по мотивам чата; реальные голоса участников не копируются.

Автовыпуск выключен до `/serial on`. Первая плановая серия выходит через 7 дней после включения; успешный ручной выпуск переносит следующий на 7 дней. Если сообщений мало или сервисы недоступны, повторная попытка выполняется через час. При выключенном боте расписание не работает; после запуска пропущенный выпуск будет обработан без очереди старых серий. Сюжет, номера, назначенные голоса и расписание сохраняются в основной SQLite-базе вместе с остальными данными бота.

Один монтаж за раз и пауза 5 минут между попытками в группе защищают небольшой сервер. Полный процесс ограничен 15 минутами, размер MP4 — 48 МБ. После ошибки доставки номер серии и сюжет не меняются. В редком случае обрыва соединения после принятой Telegram загрузки повторная попытка может доставить тот же номер снова: Bot API не предоставляет ключ идемпотентности для отправки видео.

Проверки: `python -m unittest discover -s tests`. Тест монтажа действительно собирает MP4 через FFmpeg с тестовым звуком; внешние модели, Edge TTS и Telegram в тестах заменены заглушками.

- `/start` — приветствие и помощь.
- `/reset` — удалить свою историю.
- `/myid` — показать свой Telegram ID.
- `/app` — открыть Mini App в стиле iOS 26 (кнопка «Secret AI» у поля ввода тоже открывает его): приложения в одно касание, готовые сценарии, режим ответа и модель.
- `/emojiid` — показать ID анимированного (custom) эмодзи из сообщения.
- `/mode`, `/export`, `/help` — режим ответа, выгрузка истории, справка.

Отправьте текст, голосовое до 10 минут/19 МБ или фото с подписью-вопросом. На голосовое или кружок бот отвечает текстом и голосовым; под ответами кнопок нет. Без подписи бот описывает фото. Перед ответом на голосовое показывает расшифровку. Ответы модели — на языке пользователя; служебные сообщения — на русском или английском. Ответы делятся на части до 4000 единиц UTF-16, включая эмодзи.

## Деплой на Render (Web Service)

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите Telegram-токен. Создайте ключ в [OpenAI Platform](https://platform.openai.com/api-keys).
2. В [Render](https://dashboard.render.com/) выберите **New → Web Service**, подключите GitHub и предоставьте доступ к приватному репозиторию `secret-ai`.
3. Выберите ветку `main`, язык **Python 3**, корневую директорию оставьте пустой.
4. **Build Command:** `pip install -r requirements.txt`
5. **Start Command:** `python bot.py`
6. В **Environment** добавьте `PYTHON_VERSION=3.11.11`, `TELEGRAM_TOKEN`, `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-5.6-luna` и при необходимости `ALLOWED_USERS`.
7. Для постоянной работы выберите платный экземпляр. Добавьте **Persistent Disk** с точкой монтирования `/var/data`, затем `DATABASE_PATH=/var/data/memory.db`.
8. Укажите **Health Check Path:** `/health`. HTTP-сервер слушает `0.0.0.0:$PORT`. Проверка подтверждает работу процесса, но не доступность OpenAI или Telegram.
9. Нажмите **Create Web Service**, дождитесь запуска и напишите боту `/start`.

Используется long polling: публичный webhook и отдельный домен для Telegram не нужны. Держите **один экземпляр** с одним Telegram-токеном. Не запускайте одновременно локальную копию и Render: Telegram выдаст конфликт polling. Подключённый persistent disk также исключает обычное перекрытие экземпляров при деплое.

**Ограничения бесплатного Render:** сервис засыпает после 15 минут без входящего трафика. Исходящий polling Telegram не обеспечивает постоянную работу; спящий бот не проснётся от сообщения Telegram. Без persistent disk память теряется при перезапуске/деплое. Для непрерывной работы с сохраняемой SQLite используйте платный сервис и диск.

## Локальный запуск

Нужен Python 3.10+ (рекомендуется 3.11). Создайте виртуальное окружение, установите зависимости и задайте переменные окружения средствами своей системы:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Задайте TELEGRAM_TOKEN и OPENAI_API_KEY в окружении.
python bot.py
```

`imageio-ffmpeg` поставляет FFmpeg для преобразования Telegram OGG/Opus в WAV на поддерживаемых платформах, включая Linux x86_64 Render. На другой архитектуре может потребоваться системный FFmpeg и переменная `IMAGEIO_FFMPEG_EXE` с его путём.

## Анимация «Думаю» и печать ответа (как у Mira)

Логотип Secret AI — белая звезда-искра с глазами. В Mini App она «дышит», поворачивается, оглядывается и моргает. В чате тот же логотип стоит перед «Думаю…»: при запуске бот сам создаёт набор эмодзи из `webapp/logo-emoji.webm` (владелец — владелец бота) и использует его. Telegram показывает такие эмодзи от ботов, только если у владельца бота есть Telegram Premium; иначе бот покажет обычный `✨`.

Пока модель думает, бот показывает черновик сообщения: `логотип Думаю` и таймер `0с, 1с…`, фразы меняются каждые 4 секунды. Потом ответ сам «печатается» плавной анимацией. Это нативные черновики Telegram (`sendMessageDraft`, Bot API 9.5+): они не мигают и не упираются в лимит правок. Готовый ответ отправляется обычным сообщением с кнопками. Если Telegram не поддерживает черновики, бот автоматически переходит на анимацию через редактирование сообщения.

### Свой анимированный логотип

1. Подготовьте логотип в PNG, лучше квадратный и с прозрачным фоном.
2. Сделайте из него видео-эмодзи (100×100, до 3 с, до 64 КБ):
   ```bash
   python tools/make_emoji.py logo.png emoji.webm --style pulse   # или spin / bounce
   ```
3. В [@Stickers](https://t.me/Stickers): `/newemojipack` → **Video emoji** → отправьте `emoji.webm`, укажите эмодзи-замену (например `✨`), затем `/publish`.
4. Напишите своему боту `/emojiid` и вставьте этот эмодзи из набора. Бот ответит строкой с `BRAND_EMOJI` и `BRAND_EMOJI_ID`.
5. Добавьте эти переменные в Environment на Render и перезапустите сервис.

Боты могут показывать кастомные эмодзи, только если у владельца бота есть Telegram Premium (или у бота купленный юзернейм на Fragment). Иначе Telegram отклонит эмодзи, и бот покажет обычный `BRAND_EMOJI` — ответы при этом не ломаются.

## Mini App

`/app` или кнопка меню открывают Mini App в стиле iOS 26 Liquid Glass: стеклянные карточки и плавающий таб-бар, анимированный логотип (звезда-искра с глазами дышит, оглядывается и моргает), пружинные анимации, тактильная отдача. Поддерживаются тёмная и светлая темы Telegram. Вход проверяется подписью Telegram (`initData`); `ALLOWED_USERS` действует и здесь.

- **Агент** — приветствие, выбор модели, быстрые сценарии и ваши подключения.
- **Открытия** — готовые сценарии. Нажали — запрос уходит в чат, и бот сразу отвечает. Если сценарию нужно приложение (Gmail, Notion…), Mini App сначала предложит его подключить.
- **Приложения** — каталог с поиском. Нажмите «Подключить», войдите в аккаунт сервиса, и всё. Ни URL, ни ключей вводить не нужно.
- **Настройки** — режим ответа, модель, GitHub, свой MCP-сервер, память.

### Приложения без всяких ключей

Приложения с пометкой «сразу» работают без настройки: Notion, Linear, Jira и Confluence, Asana, Sentry, Canva, Vercel, Hugging Face, Stripe. У них есть официальные удалённые MCP-серверы со стандартным OAuth. Бот сам регистрируется у сервиса как клиент (dynamic client registration). Пользователь нажимает «Подключить», входит в аккаунт и разрешает доступ. Вход идёт с PKCE, токены хранятся зашифрованными и обновляются автоматически.

Gmail, Google Calendar и большинство остальных сервисов так не умеют: Google и другие требуют один раз зарегистрировать приложение. Для них — каталог Pipedream ниже.

### Каталог приложений в одно касание (Pipedream Connect)

Каталог и вход в сервисы обеспечивает [Pipedream Connect](https://pipedream.com/docs/connect): больше 2 500 приложений с готовым OAuth. Токены аккаунтов пользователей хранит Pipedream; бот знает только ключи своего проекта.

1. Зарегистрируйтесь на [pipedream.com](https://pipedream.com), создайте **Project** и скопируйте его ID (`proj_…`) — это `PIPEDREAM_PROJECT_ID`.
2. В **Settings → API** создайте OAuth-клиент: получите `PIPEDREAM_CLIENT_ID` и `PIPEDREAM_CLIENT_SECRET`.
3. Добавьте три переменные в Environment на Render и перезапустите сервис. Для боевых пользователей окружение `production`. Его условия (бесплатный лимит, тарифы) смотрите в Pipedream.

После подключения приложение становится для модели удалённым MCP-сервером Pipedream: бот сам вызывает его инструменты, например «найди в Gmail письмо от …», «создай страницу в Notion», «что у меня в календаре завтра». Действия выполняются **без отдельного подтверждения**. Отключить приложение можно в его карточке.

### GitHub — одна кнопка

В Mini App нажмите «Подключить GitHub», разрешите доступ на GitHub и выберите репозитории. Токены и настройки на Render не нужны.

В самый первый раз GitHub покажет владельцу бота страницу «Create GitHub App»: так бот один раз создаёт себе приложение на GitHub ([App Manifest](https://docs.github.com/apps/sharing-github-apps/registering-a-github-app-from-a-manifest)). Ключи этого приложения бот сохраняет в своей базе в зашифрованном виде. После этого всем пользователям хватает одной кнопки. Токены пользователей обновляются автоматически.

Владельцем бот считает самого раннего пользователя в истории чата, а если её нет — первого, кто им воспользовался. Поэтому после нового деплоя сначала откройте бота сами. Вместо автоматического приложения можно задать `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET` своего OAuth App (callback: `https://<ваш-сервис>/oauth/github/callback`). Вход по fine-grained токену остался в карточке GitHub («Войти по токену»).

После этого просто пишите: «покажи мои репозитории», «в репо secret-ai поменяй заголовок README на …», «удали old.py», «сделай это в ветке feature и открой pull request». Бот сам смотрит и читает файлы, затем присылает **diff** (или файл `changes.diff`) с кнопками **✅ Применить / ❌ Отмена**. Без подтверждения ничего не меняется. Все правки уходят одним коммитом.

Бот умеет и удалять репозитории целиком: «удали все репозитории, кроме secret-ai». Он покажет список и кнопку **🗑 Удалить**, а затем вторую — **⚠️ Да, удалить навсегда**. Удаление необратимо. GitHub App, которое бот создаёт сам, запрашивает право Administration: Read and write. Если приложение было создано раньше, владелец один раз добавляет это право: GitHub → Settings → Developer settings → GitHub Apps → приложение бота → Permissions. При входе по токену нужен токен с правом Administration — Read and write. Если файл успели изменить после предложения, бот откажется применять и попросит повторить. Неподтверждённые изменения живут 1 час.

### Свой MCP-сервер

Настройки → «Свой MCP-сервер»: название, HTTPS-URL и ключ, если нужен. Модель вызывает инструменты сервера сама, **без отдельного подтверждения**, поэтому подключайте только доверенные сервисы. Токены хранятся в SQLite в зашифрованном виде.

## Бесплатная генерация (по умолчанию)

- **Фото:** модель Flux бесплатно — через Cloudflare Workers AI, если заданы `CF_ACCOUNT_ID` и `CF_API_TOKEN` (бесплатный аккаунт, ~сотня картинок в день, стабильно), иначе через Pollinations без ключа (примерно 1 картинка в 15 секунд, бывает очередь).
- **Видео:** бесплатных видеомоделей нет, поэтому бот делает «оживлённые кадры»: ИИ пишет сценарий, на каждую сцену рисует бесплатную картинку, ffmpeg плавно приближает и ведёт камеру, сверху — русская озвучка (OpenAI TTS).
- Платные модели остаются: впишите id модели fal / Higgsfield / Veo в настройках генерации Mini App (например `fal-ai/flux/dev`).

## Генерация фото и видео (fal.ai)

Вкладка «Генерация» в Mini App: «Создать фото», «Создать видео» и шаблоны стилей. Можно и просто написать боту «нарисуй…» или «сделай видео…». Результат приходит в чат.

- **Ключ.** Владелец бота создаёт ключ на [fal.ai](https://fal.ai) (Dashboard → API Keys, тип API), пополняет баланс и вставляет ключ в Mini App: «Генерация → Добавить ключ» или «Настройки → Генерация (fal.ai)». Ключ хранится зашифрованным, поле видит только владелец. Можно и через переменную `FAL_KEY`.
- **Модели** по умолчанию: фото — `fal-ai/flux/schnell`, видео — `fal-ai/kling-video/v2.6/pro/text-to-video`. Их меняют там же, в настройках ключа, без деплоя.
- **Видео — Kling + звуки + русская озвучка**, всё на одном ключе fal. Kling снимает сцены по 10 секунд без звука (его собственный звук — речь на китайском/английском). Затем [MMAudio](https://fal.ai/models/fal-ai/mmaudio-v2) (около $0.001 за секунду) добавляет к каждой сцене звуки по картинке: шаги, ветер, птицы, вода, город. Сверху бот кладёт русскую озвучку диктора (OpenAI TTS). 16 с, 32 с и ~1 мин собираются из сцен.
- **AnyModel** (anymodel.org, оплата в рублях): ключ — переменная `ANYMODEL_API_KEY` в Render. С ним видео идёт на `xai/grok-imagine-video` (720p, сцены по 10 с, свои звуки) + русская озвучка; другая модель — `ANYMODEL_VIDEO_MODEL` (например `xai/grok-imagine-video-1.5`), другой адрес API — `ANYMODEL_BASE`.
- **Модели чата:** только Grok 4.7: `ANYMODEL_API_KEY` / `ANYMODEL_BASE` (основной), `REFORMBOSS_API_KEY` / `REFORMBOSS_BASE` (резерв). Старые ключи и `CHAT_MODEL` не включают другие модели.
- **Память:** личка — последние 1000 сообщений; группа — хранится 10 000 сообщений: последние 600 бот видит целиком, а из более старых сам находит относящиеся к вопросу. Плюс долгая память о людях: бот сам запоминает факты (имя, город, увлечения, планы) и помнит их и в личке, и во всех группах; в личке он знает, что человек недавно писал в группах.
- **Память навсегда (Neon):** Render стирает диск при каждом деплое. Если задать `DATABASE_URL` (строка подключения Postgres, например бесплатный neon.tech), бот раз в минуту и при выключении сохраняет туда сжатую копию базы, а после деплоя восстанавливает её при запуске. Сохраняется всё: переписка, факты о людях, группы, кредиты, ключи.
- **Голос AnyModel для голосовых ответов** (личка и группы): по умолчанию голос «Дмитрий» (`edge-tts/ru-RU-DmitryNeural`); голоса AnyVoice (персонажи из кабинета) через API недоступны. Другой голос — `ANYMODEL_VOICE` = его id (`fish-farm/…`, `edge-tts/ru-RU-…`) или имена через `|`; `off` — выключить. Не нашёлся или не ответил — бот говорит обычным голосом OpenAI (в логах строка `AnyModel voice:`). В группе на голосовое бот отвечает только голосовым.
- **Голоса Fish Audio** (персонажи, тысячи голосов): `FISH_API_KEY` (fish.audio → API Keys) и `FISH_VOICE` = ссылка на голос или его ID (32 символа из ссылки `fish.audio/m/<ID>`). Либо в чате: `/voice fish <ссылка>`; `/voice fish off` — выключить. Не ответил (нет баланса и т. п.) — бот говорит голосом AnyModel/OpenAI.
- **Генерация в группе:** ответь боту реплаем или упомяни его (@бот) и напиши «создай видео …», «сделай видос на 20 секунд …» или «нарисуй картинку …». Результат приходит в группу ответом на сообщение; платит тот, кто попросил (владелец бота — бесплатно).
- **Бесплатное ИИ-видео** (Wan 2.2, LTX на Hugging Face ZeroGPU): бесплатный токен с huggingface.co/settings/tokens (тип Read) — переменная `HF_TOKEN` в Render. Каждая сцена — настоящее ИИ-видео, пока не кончилась бесплатная квота GPU (несколько роликов в день), дальше — оживлённые картинки; русская озвучка поверх. Другие пространства — `HF_SPACES=владелец/имя,…`.
- **Kling напрямую** (без fal): API Key из консоли разработчика Kling — переменная `KLING_API_KEY` в Render (старая пара `KLING_ACCESS_KEY` + `KLING_SECRET_KEY` тоже работает). С ними видео идёт на `kling-v2-6` (со звуками) + русская озвучка; другую модель задаёт `VIDEO_MODEL=kling:<model_name>`, другой адрес API — `KLING_API_BASE`.
- Можно поставить и другие модели видео: id Higgsfield (`bytedance/…`, ключ `KEY_ID:KEY_SECRET`, переменная `HF_KEY`) или Google Veo (`veo-…`, ключ Google AI Studio, переменная `GEMINI_API_KEY`) — у них свой звук и речь в кадре, но нужен платный баланс.
- **Важно для Render Free:** диск там стирается при каждом обновлении бота, и ключ, вставленный в Mini App, пропадает. Чтобы ключ не слетал, добавьте его в Render → Environment как `FAL_KEY`, а свой Telegram ID — как `OWNER_ID` (узнать ID: @userinfobot).
- **Лимиты.** 5 бесплатных фото в день на человека. Дальше — кредиты: фото стоит 1, видео — 60 (8 с), 120 (16 с), 240 (32 с), 480 (~1 мин). Пакеты кредитов: 60 / 250 / 1000 за 60 / 230 / 880 ⭐. Владелец бота генерирует без ограничений. Если генерация не удалась, кредиты возвращаются.
- Цифры задаются в `media.py` (`FREE_PHOTOS_PER_DAY`, `COST`, `PACKS`).

## Главная Mini App: секретарь и группы

- **ИИ-секретарь** — переключатель вкл/выкл прямо на главной; по нажатию — правила ответа, уведомления, инструкция подключения и последние 10 ответов (хранятся в памяти процесса).
- **Мои группы** — группы, где пользователь писал при боте: сколько сообщений бот помнит, стикеров и мемов, любимые фразы чата и регулятор «Сглыпа-режима» (Выкл / Редко / Обычно / Часто = 0 / 4 / 10 / 20 % сообщений). Менять уровень могут только админы группы (проверка через getChatMember). Кнопка «Добавить в группу» открывает t.me/<бот>?startgroup=1.

## Код, сайты и группы

- **Код файлами.** Если ответ содержит код, скрипт или конфиг (блок от 8 строк или с именем файла), бот присылает его документом, а в тексте оставляет короткое пояснение. Обычные ответы остаются текстом.
- **Сайты.** «Сделай сайт…» — модель пишет один `index.html`, бот присылает файл и публикует его по ссылке `/s/<id>` с кнопкой «Открыть сайт». Страница открывается в песочнице (CSP sandbox) и не имеет доступа к Mini App. На Render Free ссылки живут до следующего обновления бота.
- **Поиск в интернете.** Для свежих фактов модель использует встроенный web search OpenAI; если модель его не поддерживает, бот сам отключит его (или `WEB_SEARCH=0`).
- **Группы.** Бот отвечает на reply к своему сообщению и на упоминание по текущему @username (после переименования в BotFather новое имя подхватывается за 5 минут без перезапуска). Он хранит в SQLite последние 500 сообщений каждой группы с именами и передаёт модели последние 300, поэтому понимает, кто что пишет, и в стиле компании подкалывает, шутит и рифмует. В группах нет долгой анимации: сначала логотип, затем ответ на его месте. Личные приложения, GitHub и генерация в группах не используются.
- **Сам по себе.** Примерно на каждое 10-е сообщение (не чаще раза в 3 минуты) бот без спроса делает что-то одно: подкол, стикер или гифку, которые раньше кидали в этот чат, частую фразу чата, картинку-цитату (звезда «говорит» сообщение участника, с его аватаркой и именем) или демотиватор из фото чата с подписью от ИИ. Примерно в половине случаев это reply на свежее сообщение, иногда — reply на сообщение постарше, иногда просто пост в чат. Такие действия идут без логотипа и без «печатает…», чтобы их нельзя было предугадать.
- **Мемы из TikTok.** В «Сглыпа-режиме» бот иногда кидает смешное видео из TikTok (поиск через неофициальный сервис tikwm.com, без ключей; одно и то же видео в чат не повторяется). Берутся только русскоязычные видео (русское название или автор из русскоязычной страны). Если tikwm недоступен — гифка или стикер из самого чата. По просьбе: «@бот скинь мем про котов» или `/meme коты`.
- **Ссылки на TikTok.** Кидаешь боту ссылку (в группе — с упоминанием бота или ответом ему), и он «смотрит» видео: берёт описание, звук, 6 кадров и расшифровку речи или текста песни (Whisper), а потом отвечает. На просто ссылку реагирует как друг, который посмотрел; на «что за песня?» называет трек по звуку из TikTok. Если там «оригинальный звук», бот пробует угадать песню по тексту, а точно узнаёт по аудио, если задан `AUDD_API_TOKEN` (audd.io, есть бесплатный лимит). Видео берётся через tikwm.com, как и мемы.
- **Викторина (только в группах).** `/sgame` (или «@бот давай поиграем») — необычное имя команды, чтобы не срабатывали другие боты в группе; рейтинг — `/srating`, остановить игру — `/sstop` (ведущий или админ группы). В лобби игроки жмут «✋ Я играю» — отвечать могут только они; ведущий выбирает тему (всё подряд, 💬 про наш чат — вопросы по переписке группы, кино, музыка, спорт, наука, игры и аниме, Кавказ) и жмёт «▶️ Начать». 8 вопросов средней сложности, 20 секунд на ответ кнопками. Каждая карточка — анимация (quizart.py): слова вопроса вылетают по одному, плитки ответов выпрыгивают, идёт таймер, потом правильный ответ загорается зелёным; в конце растёт пьедестал. Подписи короткие: вопрос и таймер — на самой анимации. Очки: 500 за верный ответ + до 500 за скорость, +200 за серию из трёх. Вопросы пишет модель группы; заданные вопросы запоминаются (`game_asked`), и в этом чате они больше не повторяются. Если модель не ответила, берутся встроенные.
- **Мемы по просьбе:** `/q` в ответ на сообщение — цитата; `/dem` в ответ на фото (или без него — случайное фото из чата) — демотиватор. Можно и словами: «@бот цитата» в ответ на сообщение, «@бот демотиватор» в ответ на фото. Шрифты DejaVu лежат в `assets/` (лицензия в `assets/DejaVu-LICENSE.txt`).
- **Чтобы бот видел все сообщения группы**, отключите режим приватности: @BotFather → /setprivacy → выбрать бота → Disable, затем удалите бота из группы и добавьте снова (или сделайте его администратором). Без этого он видит только reply, команды и упоминания.

## ИИ-секретарь (Telegram Business)

Бот отвечает людям в личных чатах владельца аккаунта, пока тот занят. Нужен Telegram Premium.

1. @BotFather → бот → Bot Settings → **Business Mode** → включить.
2. Telegram → Настройки → **Telegram для бизнеса** → **Чат-боты** → выбрать бота, отметить чаты, разрешить «Отвечать на сообщения». Бот напишет, что подключён.
3. В личке с ботом написать, как отвечать: «отвечай всем: привет, я занят или сплю, отвечу позже, это ИИ». Модель сама вызывает инструмент `secretary_settings`. Выключить — «выключи секретаря»; статус — `/secretary`.

Как работает: на входящее сообщение секретарь отвечает по правилам владельца, внизу каждого ответа — подпись с логотипом и именем бота («✨ Имя бота · ИИ-ассистент»), чтобы собеседник видел, что пишет не владелец (коротко, на языке собеседника, ничего не обещая за владельца) и присылает владельцу заметку «кто написал → что ответил» (отключается словами «без уведомлений»). Секретарь отвечает на каждое сообщение — reply прямо на него. «выключи секретаря» / «включи секретаря» в личке с ботом срабатывают сразу, без модели. Как только владелец сам пишет кому-то в личке, секретарь замолкает во всех чатах на 10 минут — Telegram не показывает ботам статус «в сети», поэтому признак присутствия — сообщения владельца. Настройки хранятся в зашифрованном хранилище, последние строки переписки — только в памяти процесса.

## Голос и приветственный кружок

- На голосовое или кружок бот отвечает **только голосом** (без текста и без пузыря «Расшифровка»); если в ответе есть файлы или озвучка не удалась — текстом. Whisper получает язык пользователя из Telegram, поэтому короткие фразы не распознаются как другой язык.
- **Кружок-приветствие:** при первом /start новый пользователь получает видеокружок, где ИИ-ведущий говорит «Привет! Я Secret AI…». При запуске бот один раз делает его: с ключом fal — ИИ-ведущий (портрет Flux + липсинк `fal-ai/sadtalker`), без ключа или при ошибке — звезда на ножках пишет приветствие на доске (кадры заранее отрисованы `tools/render_welcome.py` в `assets/welcome-board.mp4`, на сервере только накладывается голос). Готовый кружок бот сразу кладёт в чат владельца и тихо закрепляет: после перезапуска (стёртая база на Render Free) он берёт кружок из закрепа, ничего не генерируя, и новым пользователям отправляет мгновенно по file_id (нужен OWNER_ID или любое сообщение владельца боту). Не открепляйте его. Владелец может поставить свой: записать кружок и ответить на него `/setwelcome`. `/welcome` — показать кружок.

## Claude Sonnet 4.6 через Abacus.AI RouteLLM

Добавьте переменную `ABACUS_API_KEY` (ключ с apps.abacus.ai → RouteLLM APIs). При запуске бот проверяет каталог `https://routellm.abacus.ai/v1` и подключает только Claude Sonnet 4.6, Haiku 5.5 и Opus 5.5. Gemini и автоматический маршрутизатор не включаются. ## Память и обработка ошибок

SQLite хранит последние 300 сообщений (примерно 150 пар вопрос–ответ) на пользователя. Модель видит их целиком, пока они укладываются в ~90 тыс. символов: старые длинные ответы сокращаются, самые старые сообщения отбрасываются первыми. Запись пары и обрезка истории выполняются одной транзакцией. `/reset` удаляет историю только отправителя. Сообщения обрабатываются последовательно: это сохраняет порядок диалога и сброса памяти, но долгий запрос задерживает остальных пользователей.

В памяти сохраняются текст, расшифровки и ответы. Исходные голосовые временные файлы удаляются после обработки. Фото передаётся в текущий запрос OpenAI; в SQLite остаются подпись и отметка о фото, а также ответ модели. Для повторного анализа визуальных деталей отправьте фото снова. Тексты и медиа передаются OpenAI для обработки; `store=False` отключает хранение Responses для последующего получения, но не заменяет правила хранения данных провайдера.

Ошибки отдельных сообщений перехватываются; пользователю приходит понятное уведомление. В логи выводится только тип ошибки, без ключей и содержимого диалога. Некорректная конфигурация не запускает бота. Если закончился баланс API или модель недоступна, проверьте настройки OpenAI; бот не подменяет выбранную модель другой.

## Вечная память в личке и в группах

Переписка с каждым человеком хранится целиком (до 200 000 сообщений). Последние 1000 модель читает как историю, а более старые бот находит по словам из нового вопроса (как в группах) и подкладывает модели с пометкой давности («2 мес. назад»). Так бот помнит разговоры месячной и годовой давности, не раздувая каждый запрос. `/reset` и `/wipe` стирают и это.

В группах так же: хранится вся переписка (до 300 000 сообщений на группу), последние 600 бот читает целиком, а старые находит по теме вопроса — вместе с соседними сообщениями (чтобы понимать контекст) и пометкой, когда это было.

## Итоги дня в группах

Каждый вечер в 22:00 по Москве в группах, где за сутки было от 20 сообщений, бот присылает карточку дня: сколько сообщений и участников, час пик, топ-5 самых активных и график активности по часам. Под карточкой — весёлая сводка от модели: о чём говорили и номинации (болтун дня, фраза дня — дословная цитата, момент дня, спор дня, последнее слово). `/sday` — итоги прямо сейчас; `/sday off` и `/sday on` (админы группы) выключают и включают вечернюю отправку.

### Помощник в любых чатах Telegram

Включи inline-режим у @BotFather: `/setinline` → выбери Secret AI → подсказка
`Напиши текст: перевод, правки, кратко, ответ`. Это настройка Telegram, код не может включить её через Bot API.
После обновления напиши боту `/inline`: он покажет примеры и кнопки перехода в другой чат.
В любом чате введи `@имя_бота текст`, дождись четырёх вариантов и выбери результат для отправки.
Префиксы `перевести`, `исправить`, `сократить`, `ответить` показывают только соответствующий вариант.
Перевод по умолчанию — на русский, с русского на английский; другой язык можно указать в запросе.

Используется текущая модель Grok через существующий маршрут. Передаётся только набранный текст (до 256 символов),
без личной истории, проектов, файлов, поиска или действий через приложения. Результат отправляет сам пользователь.
Telegram получает персональные ответы без общего кэша. В памяти процесса хранится до 128 результатов на 60 секунд,
ключ включает ID пользователя и хеш текста; в SQLite inline-запросы не записываются. Старые записи удаляются при
вытеснении или перезапуске, просроченные не используются. Задержка набора 0,6 с, не более одного запроса на пользователя
одновременно и одного нового обращения за 3 с; четыре общих слота и дедлайн 8 с. При ошибке доступна кнопка перехода
в личку, технический текст ошибки в чужой чат не отправляется. Для проверки живой функции нужны inline-настройка
BotFather и запрос из Telegram; локальные тесты проверяют обработчик с имитацией модели.


### Правки конкретного сообщения через реплай

В личке с ботом ответь на нужное сообщение и напиши «сократи», «переведи на немецкий»,
«исправь ошибки» или свой запрос. Если в Telegram выделена цитата, обрабатывается только она;
без цитаты — текст выбранного сообщения (или подпись). Можно дать инструкцию голосовым сообщением.
В группе ответь на сообщение бота или упомяни его при реплае на текст другого участника.
Бот должен присутствовать в этой группе; это обычный реплай, отдельный от inline-режима.

Выбранный текст имеет приоритет над активным проектом и последним документом. Для этого запроса
не передаются другие сообщения, поиск по истории, личные факты и инструменты приложений.
В личной истории сохраняются выбранный текст, инструкция и результат, поэтому дальнейший диалог
сохраняет связь с правкой. Если пришла только цитата без полного сообщения, её достаточно.
Если текст реплая недоступен, бот просит прислать его вместо выбора другого старого ответа.
Реплай на документ без выделенной цитаты сохраняет прежний разбор файла; новая загрузка также
обрабатывается как файл. Изменение создаёт новый ответ, а не редактирует старое сообщение в Telegram.
Смысловую неоднозначность вроде «не то» модель уточняет по выбранному тексту.


### «Мой день»: повседневный помощник

Новый раздел работает в личных сообщениях и включается пользователем:

- `/life on` — автоматический разбор новых сообщений на дела. Пришли голосовое, текст,
  скриншот, документ или ссылку; бот выделит отдельные задачи и следующий шаг. Связанные
  новые материалы могут дополнять существующую открытую задачу, без новой карточки.
- `/inbox` — накопить пачку сообщений без запросов к модели; `/sort` или «разбери мой завал»
  разбирает первые 12 материалов за раз, максимум на 8 дел. Можно написать сам завал после этой фразы.
- `/tasks`, `/task ID` — карточки, отдельные диалоги, материалы, подготовленные результаты,
  кнопки продолжения, завершения, паузы и возобновления. `/task off` выходит из задачи.
  «Что там с компьютером?» ищет свои открытые задачи; при нескольких совпадениях предлагает выбор.
- `/plan` — сроки, приоритеты и следующие шаги; `/review` — завершённое за местный день и остаток.
  Они работают локально без ИИ. `/prepare` или «подготовь меня к завтрашнему дню» готовит
  общий план и полезные результаты для первых 8 открытых задач; результат сохраняется отдельно в каждую задачу.
- `/life tz Europe/Berlin` — часовой пояс (новый профиль: UTC). `/routine 08:00 21:00 Europe/Berlin`
  включает утренний план и вечерний итог. `/routine off` отключает оба. Без команды рассылка не включается.
- `/remind ID_задачи через 20 минут`, `/remind ID_задачи завтра 08:00` или точная местная дата
  `/remind ID_задачи 2026-12-01 15:30`. `/remind` показывает список, `/remind cancel ID_напоминания` отменяет.
  Есть кнопка напоминания через час. В уведомлении — следующий шаг, последний подготовленный текст
  либо ссылки из материалов. Дедлайн, извлечённый ИИ, сам по себе не создаёт уведомление.
- `/life off` — обычный чат, выключает захват сообщений и закрывает активную задачу;
  напоминания и ежедневные сообщения выключаются отдельно. Реплаи на конкретный текст сохраняют
  прежнюю обработку и не попадают в общий сбор.
- `/task delete ID`, `/inbox delete ID`, `/life clear` удаляют данные после подтверждения.
  `/life export` выгружает свои задачи, материалы и результаты в JSON. `/reset` и общий `/wipe`
  также очищают соответствующие новые таблицы и расписания.

Все записи находятся в текущей SQLite-базе (`dy_*`) и включаются в существующие резервные снимки.
Входящий материал сохраняется до разбора; отказ/пустой ответ ИИ не удаляет его. Telegram file_id
сохраняет доступ к исходному файлу, отдельного копирования бинарного файла на диск нет.
Документы в этом режиме не занимают квоту файлов проектов. В каждой задаче используются только
её данные и последние ответы, без истории других задач и общих личных фактов. Кнопки проверяют
владельца, операции ограничены личкой и текущим ALLOWED_USERS. В группах сбор не включается.
Лимиты: 100 задач, 300 материалов на человека, 200 сохранённых ответов на задачу, 20 активных
разовых напоминаний. Материал — до 60 тыс. символов, исходный документ — до 19 МБ; ИИ получает
ограниченные выдержки. Оригиналы и полный извлечённый текст открываются из «Материалы».

Обработка скриншотов зависит от поддержки изображений текущей моделью: при отказе сохраняется
исходник и предлагается прислать текст, без выдуманного распознавания. Ссылки сохраняются как
материалы; их страницы не загружаются автоматически. Актуальный поиск для явного запроса
«найди» использует существующее подключение OpenAI Web Search; без него ИИ обязан сказать,
что свежий поиск недоступен, и работать с присланными материалами. Бот готовит тексты и планы,
но не отправляет письма, не покупает товары и не меняет внешние аккаунты.

Доставка работает отдельным фоновым циклом раз в 20 секунд. Разовые задания и аренды доставки
переживают перезапуск; временные ошибки повторяются до четырёх попыток, блокировка бота
останавливает ежедневные сообщения. Ежедневные события имеют уникальный ключ по человеку,
местной дате и виду (включая перевод часов); после длительного простоя не рассылается весь
пропущенный архив: ежедневное событие догоняется только в течение двух часов. Хостинг должен
быть включён. При аварии между отправкой в Telegram и записью результата возможен повтор
уведомления: внешнее API не поддерживает транзакцию с нашей SQLite. Закрытие/удаление задачи
отменяет её ожидающие напоминания. Поддержка IANA-поясов включена через `tzdata`.


### Обновлённый интерфейс Mini App

Единое графитовое оформление с синим акцентом применяется к главной, чатам/проектам Codex,
подключениям, генерации и шаблонам, голосовому экрану, групповым активностям, задачам и настройкам.
На широком экране навигация слева, на телефоне — снизу. Публичный сайт использует ту же палитру
и актуальное описание модели. Логотип остаётся узнаваемым векторным знаком без постоянной анимации.
Тема выбирается в профиле или кнопкой сверху: светлая, тёмная, системная; выбор хранится на устройстве.

На главной — быстрые действия и последние реальные чаты. В селекторе чатов есть поиск,
закрепления и до 12 собственных папок. Папки/закрепления хранятся локально с привязкой к
Telegram ID, не перемещают и не удаляют серверные диалоги; между устройствами пока не синхронизируются.
Длинная переписка монтирует последние 20 задач (пары вопрос/ответ), предыдущие загружаются
порциями по 20 с сохранением видимого сообщения. Опрос не пересоздаёт неизменившийся диалог,
textarea сохраняет фокус и черновик. При скрытии приложения опрос приостанавливается и
возобновляется при возвращении. Сохранена обработка visualViewport и безопасных отступов Telegram.

«Мой день» показывает реальные личные задачи, план и итоги из `dy_*`; можно открыть результат,
завершить, приостановить или возобновить задачу и продолжить её через Telegram deep link.
Новые `/api/day/*` проходят обычную проверку initData/allowlist; ID пользователя берётся только
из проверенных данных Telegram. Чужие карточки и результаты не выдаются; клиент не может
подменить владельца в теле запроса. Открытие экрана не включает сбор сообщений или уведомления.
Экран игр/мемов открывает существующие групповые функции, не создаёт фиктивное лобби или рейтинг.
Фото/видео и мемы по-прежнему приходят в Telegram; галерея Mini App показывает доступные шаблоны.

Убраны повторные декоративные темы, фоновые сияния, тяжёлые blur/backdrop-фильтры, каскадные
появления карточек и принудительная перерисовка индикатора навигации. Превью загружаются лениво
с фиксированной геометрией и асинхронным декодированием. Переходы короткие, учитывается
`prefers-reduced-motion`; у закрытых окон скрыто содержимое, остановлена демонстрационная
анимация. Фокус видим, модальные окна поддерживают Escape и удержание клавиатурного фокуса.

Проверки: `python -m unittest discover -s tests`, компиляция Python и `node --check` для скрипта
страницы. `node tests/interface_smoke.cjs` запускает локальный сервер с фиктивными API-ответами
и проверяет главную, студию, задачи, игры, настройки, сохранение темы, поиск/папки/закрепления,
порционную историю, фокус/черновик, границы экрана и уменьшение viewport клавиатурой на 375×812
и 1440×1000. Для запуска нужны Playwright и установленные браузеры; `SECRET_UI_CHROMIUM` задаёт
нестандартный бинарник, `SECRET_UI_SKIP_WEBKIT=1` явно отмечает WebKit как пропущенный,
`SECRET_UI_MOTION=1` проверяет обычную анимацию. Снимки и отчёт записываются в `/tmp/secret-interface-qa`.
Физический iPhone и настоящий WebView Telegram из этой среды недоступны: плавность на устройстве
нужно подтвердить после обновления; гарантии отсутствия задержек сети и модели нет.

### Secret AI Play — мини-игры

В Mini App откройте **Игры** на главной. Три игры запускаются в приложении без запросов к модели:

- **Сигнал:** пять раундов памяти на сетке 3×3, прямой или обратный порядок, три ошибки на партию. Сложность меняет длину и скорость показа. При уходе из приложения показ останавливается; его можно запустить снова.
- **Шифр:** код из четырёх разных цифр (пять на сложном уровне), подсказки «на месте / рядом», ограниченные попытки. Повтор комбинации не расходует попытку. Поддерживаются кнопки и цифровые клавиши.
- **Маршрут:** генерируемые проходимые лабиринты 7×7, 9×9 и 11×11. Цель меняется: собрать все ключи, собрать ключи по номерам или пройти спринт к выходу. Бюджет ходов рассчитан по существующему маршруту. Управление соседними клетками, кнопками или стрелками клавиатуры.

Три сложности, новые комбинации для свободной игры, фиксированное по дате **испытание дня** из трёх игр на среднем уровне (смена в 00:00 UTC). Можно повторять попытки. Рекорды по игре и сложности, достижения, последние 30 партий, лучший результат испытания за текущую сохранённую дату, сохранение незавершённой партии и копирование результата. Это локальные результаты, без общего онлайн-рейтинга; прогресс хранится в localStorage отдельно по Telegram ID и не синхронизируется между устройствами. Очистка данных браузера удаляет его. Новая партия заменяет незавершённую. Если хранилище недоступно, интерфейс сообщает об этом.

Групповые викторины `/sgame` получили три режима, выбираемых ведущим в лобби: **Классика** (8 вопросов / 20 секунд, скорость и серии), **Блиц** (6 / 10, короткие паузы), **На точность** (8 / 35, 1000 очков за правильный ответ без бонуса за скорость). Не более 20 игроков. Кнопки привязаны к уникальной партии: старые сообщения не могут присоединять к новой игре или засчитывать ответы. Проверяются диапазоны вариантов, повторные ответы и фактический дедлайн. Пропущенный вопрос сбрасывает серию; ничья за первое место засчитывает победу всем с одинаковым ненулевым максимумом. Изображения и ролики оформлены в графитово-голубой гамме; при сбое картинки лобби доступно текстом. Мемы и сериал остаются отдельными возможностями в Telegram.

Проверка:

```sh
python -m unittest discover -s tests
node --test tests/play_core.cjs
# Требуются Playwright и установленный браузер Chromium:
SECRET_PLAY_FULL=1 node tests/interface_smoke.cjs
```

`play_core.cjs` проверяет детерминированность, 450 лабиринтов с прохождением в пределах бюджета, правила кодов, прямые/обратные последовательности, неверные ходы и восстановление партии. Полная браузерная проверка проходит игры и испытание дня на мобильной и компьютерной ширине с тестовыми данными, проверяет продолжение, изоляцию пользователей и повреждённое локальное сохранение. Физические iPhone, Safari и Telegram WebView требуют отдельной проверки после автообновления хостинга.

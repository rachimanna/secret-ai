# Secret AI

Telegram-бот на Python: текстовые диалоги через OpenAI Responses API, фото (vision), голосовые через `whisper-1`, отдельная SQLite-память для каждого Telegram ID. Работает в личных сообщениях. Модель по умолчанию — `gpt-5.6-luna`.

## Команды

- `/start` — приветствие и помощь.
- `/reset` — удалить свою историю.
- `/myid` — показать свой Telegram ID.
- `/app` — открыть Mini App в стиле iOS 26 (кнопка «Secret AI» у поля ввода тоже открывает его): приложения в одно касание, готовые сценарии, режим ответа и модель.
- `/emojiid` — показать ID анимированного (custom) эмодзи из сообщения.
- `/mode`, `/export`, `/help` — режим ответа, выгрузка истории, справка.

Отправьте текст, голосовое до 10 минут/19 МБ или фото с подписью-вопросом. На голосовое или кружок бот отвечает текстом и голосовым; под ответами кнопок нет. Без подписи бот описывает фото. Перед ответом на голосовое показывает расшифровку. Ответы модели — на языке пользователя; служебные сообщения — на русском или английском. Ответы делятся на части до 4000 единиц UTF-16, включая эмодзи.

## Переменные окружения

| Имя | Значение |
| --- | --- |
| `TELEGRAM_TOKEN` | Обязательно: токен от @BotFather |
| `OPENAI_API_KEY` | Обязательно: ключ OpenAI API с доступом к модели и доступным балансом |
| `OPENAI_MODEL` | По умолчанию `gpt-5.6-luna`; для фото нужна vision-модель |
| `ALLOWED_USERS` | Telegram ID через запятую, например `123456789,987654321`. Пусто — доступ всем |
| `PORT` | HTTP-порт, по умолчанию `10000`; на Render задаётся платформой |
| `BRAND_EMOJI` | Эмодзи-логотип в «Думаю…», по умолчанию `✨`. Для анимированного логотипа — запасной символ, к которому привязан ваш эмодзи |
| `BRAND_EMOJI_ID` | ID анимированного эмодзи с вашим логотипом (см. ниже). Пусто — обычный эмодзи |
| `DRAFT_REPLIES` | `1` по умолчанию: нативный стриминг Telegram. `0` — старый режим с редактированием сообщения |
| `PUBLIC_URL` | Публичный HTTPS-адрес сервиса для Mini App. На Render берётся из `RENDER_EXTERNAL_URL` автоматически |
| `ENCRYPTION_KEY` | Ключ шифрования токенов сервисов в базе (любая длинная случайная строка). Если пусто — выводится из `TELEGRAM_TOKEN`; при смене токена бота подключения придётся сделать заново |
| `OPENAI_MODELS` | Необязательно: дополнительные модели для выбора в Mini App через запятую, например `gpt-5.6-sol,gpt-6-astra`. По умолчанию у всех `OPENAI_MODEL` |
| `PIPEDREAM_CLIENT_ID`, `PIPEDREAM_CLIENT_SECRET`, `PIPEDREAM_PROJECT_ID` | Каталог приложений в Mini App (см. ниже). Без них работает только GitHub и свой MCP |
| `PIPEDREAM_ENVIRONMENT` | `production` по умолчанию; `development` — для тестов |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | Необязательно: свой GitHub OAuth App. Без них бот сам создаёт GitHub App при первом подключении |
| `DATABASE_PATH` | По умолчанию `memory.db`; с диском Render используйте `/var/data/memory.db` |

Все секреты читаются только из окружения. `.env` автоматически не загружается. Не добавляйте реальные ключи в исходники, README, команды сборки или GitHub.

## Деплой на Render (Web Service)

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите Telegram-токен. Создайте ключ в [OpenAI Platform](https://platform.openai.com/api-keys).
2. В [Render](https://dashboard.render.com/) выберите **New → Web Service**, подключите GitHub и предоставьте доступ к приватному репозиторию `secret-ai`.
3. Выберите ветку `main`, язык **Python 3**, корневую директорию оставьте пустой.
4. **Build Command:** `pip install -r requirements.txt`
5. **Start Command:** `python bot.py`
6. В **Environment** добавьте `PYTHON_VERSION=3.11.11`, `TELEGRAM_TOKEN`, `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-5.6-luna` и при необходимости `ALLOWED_USERS`.
7. Для постоянной работы выберите платный экземпляр. Добавьте **Persistent Disk** с точкой монтирования `/var/data`, затем `DATABASE_PATH=/var/data/memory.db`.
8. Укажите **Health Check Path:** `/health`. HTTP-сервер слушает `0.0.0.0:$PORT`. Проверка подтверждает работу процесса, но не доступность OpenAI или Telegram.
9. Нажмите **Create Web Service**, дождитесь запуска и напишите боту `/start`.

Используется long polling: публичный webhook и отдельный домен для Telegram не нужны. Держите **один экземпляр** с одним Telegram-токеном. Не запускайте одновременно локальную копию и Render: Telegram выдаст конфликт polling. Подключённый persistent disk также исключает обычное перекрытие экземпляров при деплое.

**Ограничения бесплатного Render:** сервис засыпает после 15 минут без входящего трафика. Исходящий polling Telegram не обеспечивает постоянную работу; спящий бот не проснётся от сообщения Telegram. Без persistent disk память теряется при перезапуске/деплое. Для непрерывной работы с сохраняемой SQLite используйте платный сервис и диск.

## Локальный запуск

Нужен Python 3.10+ (рекомендуется 3.11). Создайте виртуальное окружение, установите зависимости и задайте переменные окружения средствами своей системы:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Задайте TELEGRAM_TOKEN и OPENAI_API_KEY в окружении.
python bot.py
```

`imageio-ffmpeg` поставляет FFmpeg для преобразования Telegram OGG/Opus в WAV на поддерживаемых платформах, включая Linux x86_64 Render. На другой архитектуре может потребоваться системный FFmpeg и переменная `IMAGEIO_FFMPEG_EXE` с его путём.

## Анимация «Думаю» и печать ответа (как у Mira)

Логотип Secret AI — белая звезда-искра с глазами. В Mini App она «дышит», поворачивается, оглядывается и моргает. В чате тот же логотип стоит перед «Думаю…»: при запуске бот сам создаёт набор эмодзи из `webapp/logo-emoji.webm` (владелец — владелец бота) и использует его. Telegram показывает такие эмодзи от ботов, только если у владельца бота есть Telegram Premium; иначе бот покажет обычный `✨`.

Пока модель думает, бот показывает черновик сообщения: `логотип Думаю` и таймер `0с, 1с…`, фразы меняются каждые 4 секунды. Потом ответ сам «печатается» плавной анимацией. Это нативные черновики Telegram (`sendMessageDraft`, Bot API 9.5+): они не мигают и не упираются в лимит правок. Готовый ответ отправляется обычным сообщением с кнопками. Если Telegram не поддерживает черновики, бот автоматически переходит на анимацию через редактирование сообщения.

### Свой анимированный логотип

1. Подготовьте логотип в PNG, лучше квадратный и с прозрачным фоном.
2. Сделайте из него видео-эмодзи (100×100, до 3 с, до 64 КБ):
   ```bash
   python tools/make_emoji.py logo.png emoji.webm --style pulse   # или spin / bounce
   ```
3. В [@Stickers](https://t.me/Stickers): `/newemojipack` → **Video emoji** → отправьте `emoji.webm`, укажите эмодзи-замену (например `✨`), затем `/publish`.
4. Напишите своему боту `/emojiid` и вставьте этот эмодзи из набора. Бот ответит строкой с `BRAND_EMOJI` и `BRAND_EMOJI_ID`.
5. Добавьте эти переменные в Environment на Render и перезапустите сервис.

Боты могут показывать кастомные эмодзи, только если у владельца бота есть Telegram Premium (или у бота купленный юзернейм на Fragment). Иначе Telegram отклонит эмодзи, и бот покажет обычный `BRAND_EMOJI` — ответы при этом не ломаются.

## Mini App

`/app` или кнопка меню открывают Mini App в стиле iOS 26 Liquid Glass: стеклянные карточки и плавающий таб-бар, анимированный логотип (звезда-искра с глазами дышит, оглядывается и моргает), пружинные анимации, тактильная отдача. Поддерживаются тёмная и светлая темы Telegram. Вход проверяется подписью Telegram (`initData`); `ALLOWED_USERS` действует и здесь.

- **Агент** — приветствие, выбор модели, быстрые сценарии и ваши подключения.
- **Открытия** — готовые сценарии. Нажали — запрос уходит в чат, и бот сразу отвечает. Если сценарию нужно приложение (Gmail, Notion…), Mini App сначала предложит его подключить.
- **Приложения** — каталог с поиском. Нажмите «Подключить», войдите в аккаунт сервиса, и всё. Ни URL, ни ключей вводить не нужно.
- **Настройки** — режим ответа, модель, GitHub, свой MCP-сервер, память.

### Приложения без всяких ключей

Приложения с пометкой «сразу» работают без настройки: Notion, Linear, Jira и Confluence, Asana, Sentry, Canva, Vercel, Hugging Face, Stripe. У них есть официальные удалённые MCP-серверы со стандартным OAuth. Бот сам регистрируется у сервиса как клиент (dynamic client registration). Пользователь нажимает «Подключить», входит в аккаунт и разрешает доступ. Вход идёт с PKCE, токены хранятся зашифрованными и обновляются автоматически.

Gmail, Google Calendar и большинство остальных сервисов так не умеют: Google и другие требуют один раз зарегистрировать приложение. Для них — каталог Pipedream ниже.

### Каталог приложений в одно касание (Pipedream Connect)

Каталог и вход в сервисы обеспечивает [Pipedream Connect](https://pipedream.com/docs/connect): больше 2 500 приложений с готовым OAuth. Токены аккаунтов пользователей хранит Pipedream; бот знает только ключи своего проекта.

1. Зарегистрируйтесь на [pipedream.com](https://pipedream.com), создайте **Project** и скопируйте его ID (`proj_…`) — это `PIPEDREAM_PROJECT_ID`.
2. В **Settings → API** создайте OAuth-клиент: получите `PIPEDREAM_CLIENT_ID` и `PIPEDREAM_CLIENT_SECRET`.
3. Добавьте три переменные в Environment на Render и перезапустите сервис. Для боевых пользователей окружение `production`. Его условия (бесплатный лимит, тарифы) смотрите в Pipedream.

После подключения приложение становится для модели удалённым MCP-сервером Pipedream: бот сам вызывает его инструменты, например «найди в Gmail письмо от …», «создай страницу в Notion», «что у меня в календаре завтра». Действия выполняются **без отдельного подтверждения**. Отключить приложение можно в его карточке.

### GitHub — одна кнопка

В Mini App нажмите «Подключить GitHub», разрешите доступ на GitHub и выберите репозитории. Токены и настройки на Render не нужны.

В самый первый раз GitHub покажет владельцу бота страницу «Create GitHub App»: так бот один раз создаёт себе приложение на GitHub ([App Manifest](https://docs.github.com/apps/sharing-github-apps/registering-a-github-app-from-a-manifest)). Ключи этого приложения бот сохраняет в своей базе в зашифрованном виде. После этого всем пользователям хватает одной кнопки. Токены пользователей обновляются автоматически.

Владельцем бот считает самого раннего пользователя в истории чата, а если её нет — первого, кто им воспользовался. Поэтому после нового деплоя сначала откройте бота сами. Вместо автоматического приложения можно задать `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET` своего OAuth App (callback: `https://<ваш-сервис>/oauth/github/callback`). Вход по fine-grained токену остался в карточке GitHub («Войти по токену»).

После этого просто пишите: «покажи мои репозитории», «в репо secret-ai поменяй заголовок README на …», «удали old.py», «сделай это в ветке feature и открой pull request». Бот сам смотрит и читает файлы, затем присылает **diff** (или файл `changes.diff`) с кнопками **✅ Применить / ❌ Отмена**. Без подтверждения ничего не меняется. Все правки уходят одним коммитом.

Бот умеет и удалять репозитории целиком: «удали все репозитории, кроме secret-ai». Он покажет список и кнопку **🗑 Удалить**, а затем вторую — **⚠️ Да, удалить навсегда**. Удаление необратимо. GitHub App, которое бот создаёт сам, запрашивает право Administration: Read and write. Если приложение было создано раньше, владелец один раз добавляет это право: GitHub → Settings → Developer settings → GitHub Apps → приложение бота → Permissions. При входе по токену нужен токен с правом Administration — Read and write. Если файл успели изменить после предложения, бот откажется применять и попросит повторить. Неподтверждённые изменения живут 1 час.

### Свой MCP-сервер

Настройки → «Свой MCP-сервер»: название, HTTPS-URL и ключ, если нужен. Модель вызывает инструменты сервера сама, **без отдельного подтверждения**, поэтому подключайте только доверенные сервисы. Токены хранятся в SQLite в зашифрованном виде.

## Zapier: 8000+ приложений без настройки

Первым в списке «сразу» стоит **Zapier**. Пользователь нажимает «Подключить», входит в свой (можно бесплатный) аккаунт Zapier и там выбирает, какие приложения и действия доступны боту: Gmail, Google Календарь, Таблицы, Slack, Trello и ещё 8000. Владельцу бота ничего настраивать не нужно; на бесплатном плане Zapier примерно 100 задач в месяц (каждый вызов инструмента — около 2 задач). Ещё ~30 сервисов (Notion, Linear, Jira, ClickUp, Todoist, monday.com, Miro, Figma, PayPal, Supabase, Cloudflare и др.) подключаются напрямую по OAuth. Каталог Pipedream (2500+ приложений) включается переменными `PIPEDREAM_*`, но для внешних пользователей Pipedream Connect платный.

## Бесплатная генерация (по умолчанию)

- **Фото:** модель Flux бесплатно — через Cloudflare Workers AI, если заданы `CF_ACCOUNT_ID` и `CF_API_TOKEN` (бесплатный аккаунт, ~сотня картинок в день, стабильно), иначе через Pollinations без ключа (примерно 1 картинка в 15 секунд, бывает очередь).
- **Видео:** бесплатных видеомоделей нет, поэтому бот делает «оживлённые кадры»: ИИ пишет сценарий, на каждую сцену рисует бесплатную картинку, ffmpeg плавно приближает и ведёт камеру, сверху — русская озвучка (OpenAI TTS).
- Платные модели остаются: впишите id модели fal / Higgsfield / Veo в настройках генерации Mini App (например `fal-ai/flux/dev`).

## Генерация фото и видео (fal.ai)

Вкладка «Генерация» в Mini App: «Создать фото», «Создать видео» и шаблоны стилей. Можно и просто написать боту «нарисуй…» или «сделай видео…». Результат приходит в чат.

- **Ключ.** Владелец бота создаёт ключ на [fal.ai](https://fal.ai) (Dashboard → API Keys, тип API), пополняет баланс и вставляет ключ в Mini App: «Генерация → Добавить ключ» или «Настройки → Генерация (fal.ai)». Ключ хранится зашифрованным, поле видит только владелец. Можно и через переменную `FAL_KEY`.
- **Модели** по умолчанию: фото — `fal-ai/flux/schnell`, видео — `fal-ai/kling-video/v2.6/pro/text-to-video`. Их меняют там же, в настройках ключа, без деплоя.
- **Видео — Kling + звуки + русская озвучка**, всё на одном ключе fal. Kling снимает сцены по 10 секунд без звука (его собственный звук — речь на китайском/английском). Затем [MMAudio](https://fal.ai/models/fal-ai/mmaudio-v2) (около $0.001 за секунду) добавляет к каждой сцене звуки по картинке: шаги, ветер, птицы, вода, город. Сверху бот кладёт русскую озвучку диктора (OpenAI TTS). 16 с, 32 с и ~1 мин собираются из сцен.
- **AnyModel** (anymodel.org, оплата в рублях): ключ — переменная `ANYMODEL_API_KEY` в Render. С ним видео идёт на `xai/grok-imagine-video` (720p, сцены по 10 с, свои звуки) + русская озвучка; другая модель — `ANYMODEL_VIDEO_MODEL` (например `xai/grok-imagine-video-1.5`), другой адрес API — `ANYMODEL_BASE`.
- **Модели чата:** **Claude Opus 4.6** (по умолчанию) через AnyModel (`cc/claude-opus-4-6`, работает с инструментами бота: видео, фото, секретарь) и **GPT 6.1 Sol**. Другая модель по умолчанию — `CHAT_MODEL` (например `anymodel:cc/claude-opus-4-6`). Каждая модель на вопрос «кто ты / кто тебя создал» честно называет себя и свою компанию.
- **Память:** личка — последние 1000 сообщений; группа — хранится 10 000 сообщений: последние 600 бот видит целиком, а из более старых сам находит относящиеся к вопросу. Плюс долгая память о людях: бот сам запоминает факты (имя, город, увлечения, планы) и помнит их и в личке, и во всех группах; в личке он знает, что человек недавно писал в группах.
- **Память навсегда (Neon):** Render стирает диск при каждом деплое. Если задать `DATABASE_URL` (строка подключения Postgres, например бесплатный neon.tech), бот раз в минуту и при выключении сохраняет туда сжатую копию базы, а после деплоя восстанавливает её при запуске. Сохраняется всё: переписка, факты о людях, группы, кредиты, ключи.
- **Голос AnyModel для голосовых ответов** (личка и группы): по умолчанию голос «Дмитрий» (`edge-tts/ru-RU-DmitryNeural`); голоса AnyVoice (персонажи из кабинета) через API недоступны. Другой голос — `ANYMODEL_VOICE` = его id (`fish-farm/…`, `edge-tts/ru-RU-…`) или имена через `|`; `off` — выключить. Не нашёлся или не ответил — бот говорит обычным голосом OpenAI (в логах строка `AnyModel voice:`). В группе на голосовое бот отвечает только голосовым.
- **Голоса Fish Audio** (персонажи, тысячи голосов): `FISH_API_KEY` (fish.audio → API Keys) и `FISH_VOICE` = ссылка на голос или его ID (32 символа из ссылки `fish.audio/m/<ID>`). Либо в чате: `/voice fish <ссылка>`; `/voice fish off` — выключить. Не ответил (нет баланса и т. п.) — бот говорит голосом AnyModel/OpenAI.
- **Генерация в группе:** ответь боту реплаем или упомяни его (@бот) и напиши «создай видео …», «сделай видос на 20 секунд …» или «нарисуй картинку …». Результат приходит в группу ответом на сообщение; платит тот, кто попросил (владелец бота — бесплатно).
- **Бесплатное ИИ-видео** (Wan 2.2, LTX на Hugging Face ZeroGPU): бесплатный токен с huggingface.co/settings/tokens (тип Read) — переменная `HF_TOKEN` в Render. Каждая сцена — настоящее ИИ-видео, пока не кончилась бесплатная квота GPU (несколько роликов в день), дальше — оживлённые картинки; русская озвучка поверх. Другие пространства — `HF_SPACES=владелец/имя,…`.
- **Kling напрямую** (без fal): API Key из консоли разработчика Kling — переменная `KLING_API_KEY` в Render (старая пара `KLING_ACCESS_KEY` + `KLING_SECRET_KEY` тоже работает). С ними видео идёт на `kling-v2-6` (со звуками) + русская озвучка; другую модель задаёт `VIDEO_MODEL=kling:<model_name>`, другой адрес API — `KLING_API_BASE`.
- Можно поставить и другие модели видео: id Higgsfield (`bytedance/…`, ключ `KEY_ID:KEY_SECRET`, переменная `HF_KEY`) или Google Veo (`veo-…`, ключ Google AI Studio, переменная `GEMINI_API_KEY`) — у них свой звук и речь в кадре, но нужен платный баланс.
- **Важно для Render Free:** диск там стирается при каждом обновлении бота, и ключ, вставленный в Mini App, пропадает. Чтобы ключ не слетал, добавьте его в Render → Environment как `FAL_KEY`, а свой Telegram ID — как `OWNER_ID` (узнать ID: @userinfobot).
- **Лимиты.** 5 бесплатных фото в день на человека. Дальше — кредиты: фото стоит 1, видео — 60 (8 с), 120 (16 с), 240 (32 с), 480 (~1 мин). Пакеты кредитов: 60 / 250 / 1000 за 60 / 230 / 880 ⭐. Владелец бота генерирует без ограничений. Если генерация не удалась, кредиты возвращаются.
- Цифры задаются в `media.py` (`FREE_PHOTOS_PER_DAY`, `COST`, `PACKS`).

## Главная Mini App: секретарь и группы

- **ИИ-секретарь** — переключатель вкл/выкл прямо на главной; по нажатию — правила ответа, уведомления, инструкция подключения и последние 10 ответов (хранятся в памяти процесса).
- **Мои группы** — группы, где пользователь писал при боте: сколько сообщений бот помнит, стикеров и мемов, любимые фразы чата и регулятор «Сглыпа-режима» (Выкл / Редко / Обычно / Часто = 0 / 4 / 10 / 20 % сообщений). Менять уровень могут только админы группы (проверка через getChatMember). Кнопка «Добавить в группу» открывает t.me/<бот>?startgroup=1.

## Код, сайты и группы

- **Код файлами.** Если ответ содержит код, скрипт или конфиг (блок от 8 строк или с именем файла), бот присылает его документом, а в тексте оставляет короткое пояснение. Обычные ответы остаются текстом.
- **Сайты.** «Сделай сайт…» — модель пишет один `index.html`, бот присылает файл и публикует его по ссылке `/s/<id>` с кнопкой «Открыть сайт». Страница открывается в песочнице (CSP sandbox) и не имеет доступа к Mini App. На Render Free ссылки живут до следующего обновления бота.
- **Поиск в интернете.** Для свежих фактов модель использует встроенный web search OpenAI; если модель его не поддерживает, бот сам отключит его (или `WEB_SEARCH=0`).
- **Группы.** Бот отвечает на reply к своему сообщению и на упоминание по текущему @username (после переименования в BotFather новое имя подхватывается за 5 минут без перезапуска). Он хранит в SQLite последние 500 сообщений каждой группы с именами и передаёт модели последние 300, поэтому понимает, кто что пишет, и в стиле компании подкалывает, шутит и рифмует. В группах нет долгой анимации: сначала логотип, затем ответ на его месте. Личные приложения, GitHub и генерация в группах не используются.
- **Сам по себе.** Примерно на каждое 10-е сообщение (не чаще раза в 3 минуты) бот без спроса делает что-то одно: подкол, стикер или гифку, которые раньше кидали в этот чат, частую фразу чата, картинку-цитату (звезда «говорит» сообщение участника, с его аватаркой и именем) или демотиватор из фото чата с подписью от ИИ. Примерно в половине случаев это reply на свежее сообщение, иногда — reply на сообщение постарше, иногда просто пост в чат. Такие действия идут без логотипа и без «печатает…», чтобы их нельзя было предугадать.
- **Мемы из TikTok.** В «Сглыпа-режиме» бот иногда кидает смешное видео из TikTok (поиск через неофициальный сервис tikwm.com, без ключей; одно и то же видео в чат не повторяется). Берутся только русскоязычные видео (русское название или автор из русскоязычной страны). Если tikwm недоступен — гифка или стикер из самого чата. По просьбе: «@бот скинь мем про котов» или `/meme коты`.
- **Ссылки на TikTok.** Кидаешь боту ссылку (в группе — с упоминанием бота или ответом ему), и он «смотрит» видео: берёт описание, звук, 6 кадров и расшифровку речи или текста песни (Whisper), а потом отвечает. На просто ссылку реагирует как друг, который посмотрел; на «что за песня?» называет трек по звуку из TikTok. Если там «оригинальный звук», бот пробует угадать песню по тексту, а точно узнаёт по аудио, если задан `AUDD_API_TOKEN` (audd.io, есть бесплатный лимит). Видео берётся через tikwm.com, как и мемы.
- **Викторина (только в группах).** `/sgame` (или «@бот давай поиграем») — необычное имя команды, чтобы не срабатывали другие боты в группе; рейтинг — `/srating`, остановить игру — `/sstop` (ведущий или админ группы). В лобби игроки жмут «✋ Я играю» — отвечать могут только они; ведущий выбирает тему (всё подряд, 💬 про наш чат — вопросы по переписке группы, кино, музыка, спорт, наука, игры и аниме, Кавказ) и жмёт «▶️ Начать». 8 вопросов средней сложности, 20 секунд на ответ кнопками. Каждая карточка — анимация (quizart.py): слова вопроса вылетают по одному, плитки ответов выпрыгивают, идёт таймер, потом правильный ответ загорается зелёным; в конце растёт пьедестал. Подписи короткие: вопрос и таймер — на самой анимации. Очки: 500 за верный ответ + до 500 за скорость, +200 за серию из трёх. Вопросы пишет модель группы; заданные вопросы запоминаются (`game_asked`), и в этом чате они больше не повторяются. Если модель не ответила, берутся встроенные.
- **Мемы по просьбе:** `/q` в ответ на сообщение — цитата; `/dem` в ответ на фото (или без него — случайное фото из чата) — демотиватор. Можно и словами: «@бот цитата» в ответ на сообщение, «@бот демотиватор» в ответ на фото. Шрифты DejaVu лежат в `assets/` (лицензия в `assets/DejaVu-LICENSE.txt`).
- **Чтобы бот видел все сообщения группы**, отключите режим приватности: @BotFather → /setprivacy → выбрать бота → Disable, затем удалите бота из группы и добавьте снова (или сделайте его администратором). Без этого он видит только reply, команды и упоминания.

## ИИ-секретарь (Telegram Business)

Бот отвечает людям в личных чатах владельца аккаунта, пока тот занят. Нужен Telegram Premium.

1. @BotFather → бот → Bot Settings → **Business Mode** → включить.
2. Telegram → Настройки → **Telegram для бизнеса** → **Чат-боты** → выбрать бота, отметить чаты, разрешить «Отвечать на сообщения». Бот напишет, что подключён.
3. В личке с ботом написать, как отвечать: «отвечай всем: привет, я занят или сплю, отвечу позже, это ИИ». Модель сама вызывает инструмент `secretary_settings`. Выключить — «выключи секретаря»; статус — `/secretary`.

Как работает: на входящее сообщение секретарь отвечает по правилам владельца, внизу каждого ответа — подпись с логотипом и именем бота («✨ Имя бота · ИИ-ассистент»), чтобы собеседник видел, что пишет не владелец (коротко, на языке собеседника, ничего не обещая за владельца) и присылает владельцу заметку «кто написал → что ответил» (отключается словами «без уведомлений»). Секретарь отвечает на каждое сообщение — reply прямо на него. «выключи секретаря» / «включи секретаря» в личке с ботом срабатывают сразу, без модели. Как только владелец сам пишет кому-то в личке, секретарь замолкает во всех чатах на 10 минут — Telegram не показывает ботам статус «в сети», поэтому признак присутствия — сообщения владельца. Настройки хранятся в зашифрованном хранилище, последние строки переписки — только в памяти процесса.

## Голос и приветственный кружок

- На голосовое или кружок бот отвечает **только голосом** (без текста и без пузыря «Расшифровка»); если в ответе есть файлы или озвучка не удалась — текстом. Whisper получает язык пользователя из Telegram, поэтому короткие фразы не распознаются как другой язык.
- **Кружок-приветствие:** при первом /start новый пользователь получает видеокружок, где ИИ-ведущий говорит «Привет! Я Secret AI…». При запуске бот один раз делает его: с ключом fal — ИИ-ведущий (портрет Flux + липсинк `fal-ai/sadtalker`), без ключа или при ошибке — звезда на ножках пишет приветствие на доске (кадры заранее отрисованы `tools/render_welcome.py` в `assets/welcome-board.mp4`, на сервере только накладывается голос). Готовый кружок бот сразу кладёт в чат владельца и тихо закрепляет: после перезапуска (стёртая база на Render Free) он берёт кружок из закрепа, ничего не генерируя, и новым пользователям отправляет мгновенно по file_id (нужен OWNER_ID или любое сообщение владельца боту). Не открепляйте его. Владелец может поставить свой: записать кружок и ответить на него `/setwelcome`. `/welcome` — показать кружок.

## Claude Sonnet 5.5 через Abacus.AI RouteLLM

Добавьте в Render переменную `ABACUS_API_KEY` (ключ с apps.abacus.ai → RouteLLM APIs). При запуске бот находит в списке моделей вашего аккаунта Sonnet 5.5 и добавляет «Claude Sonnet 5.5» в выбор модели Mini App (точный id можно задать `ABACUS_MODEL`). Запросы идут в OpenAI-совместимый `https://routellm.abacus.ai/v1/chat/completions` со стримингом, понимают фото. Инструменты (приложения, GitHub, генерация, поиск в интернете) работают только с моделями OpenAI; для них выберите GPT.

## Память и обработка ошибок

SQLite хранит последние 300 сообщений (примерно 150 пар вопрос–ответ) на пользователя. Модель видит их целиком, пока они укладываются в ~90 тыс. символов: старые длинные ответы сокращаются, самые старые сообщения отбрасываются первыми. Запись пары и обрезка истории выполняются одной транзакцией. `/reset` удаляет историю только отправителя. Сообщения обрабатываются последовательно: это сохраняет порядок диалога и сброса памяти, но долгий запрос задерживает остальных пользователей.

В памяти сохраняются текст, расшифровки и ответы. Исходные голосовые временные файлы удаляются после обработки. Фото передаётся в текущий запрос OpenAI; в SQLite остаются подпись и отметка о фото, а также ответ модели. Для повторного анализа визуальных деталей отправьте фото снова. Тексты и медиа передаются OpenAI для обработки; `store=False` отключает хранение Responses для последующего получения, но не заменяет правила хранения данных провайдера.

Ошибки отдельных сообщений перехватываются; пользователю приходит понятное уведомление. В логи выводится только тип ошибки, без ключей и содержимого диалога. Некорректная конфигурация не запускает бота. Если закончился баланс API или модель недоступна, проверьте настройки OpenAI; бот не подменяет выбранную модель другой.

# Восстановление сообщений на hCloud / h1cloud

Функция выключена по умолчанию. Обычный Bot API не сообщает об удалениях в супергруппе:
используется отдельная пользовательская сессия Telethon, читающая журнал администратора.
Сам пользовательский аккаунт ничего не отправляет. Копии публикует исходный бот.

## 1. Подготовить сессию у себя на компьютере

Помощник с видимыми полями и кнопками «Вставить» открывается локально в браузере:
`python tools/guard_login_web.py`. В нём не требуется нажимать Enter: заполните поля,
нажмите «Продолжить», затем введите код и, если нужно, пароль, нажимая «Подтвердить».
Все введённые значения видны только в локальном окне; не публикуйте его снимки.
Не закрывайте окно запуска программы до завершения входа. Ввод и ответы не пишутся
в журналы и не сохраняются открытым текстом. Браузер общается только с сервером
на 127.0.0.1, защищённым одноразовым ключом доступа. Для Windows также доступен
запуск через `deploy/guard_windows.cmd` после копирования его в корень проекта.

Нужны собственные `api_id` / `api_hash` с my.telegram.org и аккаунт-администратор нужной
супергруппы. Откройте обычный терминал, не веб-консоль хостинга. Для отдельного помощника
достаточно Python 3.12+ и пакетов:

```sh
python -m pip install "Telethon>=1.45,<2" "cryptography>=42,<46"
python tools/guard_login.py
```

Помощник последовательно запросит api_id, api_hash, ключ шифрования, номер телефона,
код входа из Telegram и пароль двухэтапной проверки, если он включён. В консольном
помощнике api_hash виден, остальные секреты скрыты; в браузерном помощнике видны
все поля. Ключ шифрования должен совпадать с `ENCRYPTION_KEY` из `.env` бота
на сервере. Если там `ENCRYPTION_KEY` пустой, используйте `TELEGRAM_TOKEN` этого бота.
Помощник сохраняет API-данные и авторизацию в зашифрованный `.guard-session.enc`.
Файл не перезаписывается; другое имя можно задать `--output .guard-session-new.enc`.

Не присылайте коды, пароль, ключ шифрования и файл сессии в чат. Не добавляйте их в GitHub.
Авторизацию можно отозвать в Telegram → Настройки → Устройства; после этого потребуется
повторный локальный вход и замена файла на сервере.

## 2. Загрузить на хостинг

После установки кода с этой функцией остановите бота в панели. В «Файлах» загрузите
`.guard-session.enc` в ту же папку, где находятся `bot.py` и `.env`. Добавьте в `.env`:

```dotenv
GUARD_ENABLED=1
GUARD_SESSION_FILE=.guard-session.enc
```

Оставьте прежние `TELEGRAM_TOKEN` и `ENCRYPTION_KEY` без изменений. Не запускайте одну
пользовательскую сессию одновременно на двух хостингах. Наблюдатель запускается в том
же процессе и не требует второго порта или отдельной платной службы. Тестовая копия
бота его не запускает. При обычном перезапуске повторный вход не нужен, если сохранены
файл и ключ. При замене/очистке диска загрузите файл снова: он не входит в снимки базы.

## 3. Выбрать группу

Аккаунт-наблюдатель должен находиться в супергруппе и иметь права администратора.
Бот должен иметь возможность отправлять нужные виды сообщений и читать сведения
об администраторах. Владелец группы от своего аккаунта пишет:

```
/guard on
/guard status
```

Выключение: `/guard off`. Обычные администраторы и анонимные отправители не могут
менять настройку. Если установлен ALLOWED_USERS, владелец также должен входить в него.

После включения бот сохраняет только свои новые сообщения и их последние успешные
правки в этой супергруппе. Удаление администратором обнаруживается при опросе журнала
примерно раз в 20 секунд, с учётом сети и лимитов Telegram. Удаления текущим владельцем
группы и самим ботом не восстанавливаются. При отсутствии достоверных сведений о
владельце восстановление откладывается.

Поддерживаются текст с entities, фото, видео, анимации, аудио, голосовые, документы,
стикеры и видеокружки. При наличии сохраняется тема форума и ссылка на исходное
сообщение, если оно ещё доступно. Альбомы восстанавливаются отдельными сообщениями.
Опросы, сервисные сообщения, эфемерные сообщения, автоматические пересылки и сообщения
с интерактивными callback-кнопками не восстанавливаются. URL-кнопки сохраняются.
Новая копия имеет новый ID и время; реакции, просмотры и закрепление не переносятся.
Телефонный аккаунт не используется для переписки или отправки копий.

Кэш зашифрован тем же ключом, что подключения; ограничен 48 часами и 1000 сообщениями
на группу. Он и позиция чтения журнала входят в существующие снимки SQLite. Старые
сообщения, отправленные до включения, восстановить нельзя. При большом пропуске
журнала (более 200 новых событий удаления за проход) автоматическое восстановление
этого прохода не выполняется; `/guard status` сообщает о необходимости выключить и
включить функцию заново. При выключении кэш группы удаляется.

Против циклических удалений действует пауза: до 3 попыток на цепочку одного сообщения
за 10 минут и до 10 отправок группы за минуту; затем обработка продолжается после
освобождения лимита. RetryAfter/FloodWait Telegram соблюдаются. Перед отправкой
фиксируется попытка. После неоднозначного таймаута или аварии она не повторяется
автоматически: копия могла уже уйти, и слепой повтор создал бы дубликаты. Это видно
в числе неподтверждённых отправок в `/guard status`. Поэтому гарантии восстановления
каждого сообщения при любых сбоях нет.

## Проверки

`python -m unittest discover -s tests -p test_message_guard.py` проверяет шифрование,
владельца, изоляцию групп, повторные события, таймауты, лимиты, media file_id и реальные
объекты Telethon. Полный Verify использует фиктивные Telegram API-ответы. Настоящий
вход аккаунта, права конкретной группы и отправка в неё проверяются владельцем после
подключения; CI не входит в Telegram и не отправляет реальные сообщения.
